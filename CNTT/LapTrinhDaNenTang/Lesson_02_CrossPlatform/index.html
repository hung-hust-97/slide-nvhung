CÁC MÔ HÌNH KIẾN TRÚC PHẦN MỀM MOBILE

MVC — Model-View-Controller

Phân tách rõ ràng: Display (View) — Processing (Controller) — Data (Model). Pattern cơ bản nhất, dễ hiểu, phổ biến trong iOS native development.

Ví dụ: iOS UIKit ViewController, Android Activity

MVVM — Model-View-ViewModel

Hỗ trợ two-way data binding. ViewModel làm trung gian giữa View và Model. Phổ biến trên Android (Jetpack ViewModel), WPF, Flutter.

Ví dụ: Android ViewModel, SwiftUI View, Flutter Provider/Riverpod

Three-Layer Architecture

Presentation — Business (Domain) — Data layers tách biệt. Dễ bảo trì, test, mở rộng. Flutter Clean Architecture dùng pattern này.

Ví dụ: Flutter Clean Architecture, Android Clean Architecture

✨ XU HƯỚNG HIỆN ĐẠI

BLoC Pattern (Business Logic Component) kết hợp MVVM + reactive streams. Dùng trong enterprise Flutter apps (Google, Grab). Tách biệt hoàn toàn UI và business logic.

data class User(

  val name: String,

class UserViewModel(
  private val repo: UserRepository
): ViewModel() {
  private val _users =
    MutableStateFlow<UiState>(UiState.Loading)
  val users: StateFlow<UiState> = _users

  fun loadUsers() {
    viewModelScope.launch {
      _users.value = UiState.Loading
      _users.value = repo.getUsers()
        .fold(
          onSuccess = { UiState.Success(it) },
          onFailure = { UiState.Error(it) }
        )
    }
  }
}

ANDROID APPLICATION ARCHITECTURE — CHI TIẾT

Application Layer

User-created apps nằm ở đây. APK = Android Package. Google signs APK khi upload lên Play Store. App Signing service lưu private keys.

Application Framework

Higher-level services qua Java/Kotlin classes. Activity Manager, Window Manager, Content Providers, Notification Manager.

Android Runtime

Dalvik/ART virtual machine. Mỗi app có VM riêng → security sandbox. Write once, run everywhere.

Linux Kernel

Memory management, process scheduling, security, driver model. Hardware abstraction layer.

Android Sandbox Security

1

Separate Sandbox

Mỗi app có process ID riêng. File permissions restricted — app chỉ đọc file của mình.

2

Data Sharing có kiểm soát

App share data qua Content Provider. Quyền truy cập: Address, Phone Status, SMS phải xin permission runtime.

"Android: mỗi app là 1 process riêng với private VM. iOS: sandbox riêng nhưng không có VM — code chạy trực tiếp."

Nếu KHÔNG dùng cross-platform

iOS Team

Swift/SwiftUI developer. macOS + Xcode bắt buộc. Code iOS-only.

Android Team

Kotlin/Java developer. Android Studio. Code Android-only.

Kết quả

2 codebase riêng biệt, 2 team, 2 timeline, chi phí x2.

Nếu DÙNG cross-platform

1 Team

Dart (Flutter), JavaScript (RN), hoặc C# (Xamarin). 1 codebase cho cả iOS + Android.

1 Codebase

Shared logic, shared UI (hoặc platform-adaptive). Deploy đồng thời lên cả 2 stores.

Kết quả

Tiết kiệm 40-50% chi phí, development time nhanh hơn 40%.

TIÊU CHÍ ĐÁNH GIÁ CROSS-PLATFORM

1

Target User Group

App chỉ cho Android, chỉ cho iOS, hay cả 2? Nếu chỉ 1 nền tảng → native có thể tốt hơn. Nếu cả 2+ → cross-platform tiết kiệm.

2

Budget

Ngân sách hạn chế? Cross-platform giảm 50% chi phí phát triển. Startup? Indie developer? → cross-platform recommended.

3

User Experience Expectations

Kỳ vọng UX "native-like" hay chấp nhận "good enough"? Game, AR/VR → native. Business app, MVP → cross-platform OK.

4

Payment Solution

In-app purchase (IAP) khác nhau trên iOS (Apple takes 30%) và Android (Google takes 30%). Subscription model cần platform-specific integration.

"Cross-platform apps: phát triển nhanh hơn, rẻ hơn — nhưng thường không đạt chất lượng native 100%."

FLUTTER HIGHLIGHTS — VÌ SAO CHỌN FLUTTER

Custom Widgets — UI nhất quán tuyệt đối

Flutter KHÔNG dùng native widgets. Dùng Skia graphics engine vẽ pixel riêng → UI nhất quán 100% trên mọi nền tảng. Không bị lag khi iOS/Android update UI guidelines.

Dart — JIT + AOT Compilation

JIT (Just In Time) trong development: Hot Reload <1 giây. AOT (Ahead Of Time) trong production: native code tối ưu. Dart cũng compile thành JavaScript → web support.

Strong typing, null safety, clean syntax. Dễ học hơn Kotlin, nhanh hơn JavaScript về type safety.

High Performance — Direct Native Access

Flutter giao tiếp trực tiếp với GPU qua Skia, không qua native bridge như React Native. Platform channels cho native API access khi cần. 60 FPS, 120 FPS trên ProMotion iPhone.

REACT NATIVE — ĐẶC ĐIỂM VÀ HẠN CHẾ

Ưu điểm React Native

JavaScript Ecosystem

1 triệu npm packages. React dev từ web chuyển sang mobile dễ dàng. Shared knowledge với React web projects.

New Architecture (Fabric)

RN 0.76+ với JSI thay bridge cũ. Synchronous native calls, better concurrency. Performance gần bằng native.

Expo Framework

Development đơn giản hơn, không cần Xcode/Android Studio. OTA updates — fix bug không cần re-submit app store.

Hạn chế React Native

Bridge overhead

Legacy bridge: async communication giữa JS và native. Có thể gây lag trong animation phức tạp. Đã cải thiện với New Architecture.

Third-party library quality

npm có nhiều package nhưng chất lượng không đồng đều. Deprecated packages, abandoned projects phổ biến.

Platform-specific differences

Vẫn có những khác biệt UI nhỏ giữa iOS/Android. "Learn once, write anywhere" ≠ "Write once, run anywhere".

FLUTTER PLATFORM CHANNELS — GỌI NATIVE API

Khi nào cần Platform Channels?

Flutter không cover 100% native APIs. Platform channels cho phép gọi Swift/Kotlin code từ Dart khi cần.

Khi nào cần?

  • API iOS/Android mới nhất chưa có Flutter plugin
  • Performance-critical native code
  • Third-party SDK chỉ có native version
  • Hardware access đặc biệt (Bluetooth LE, NFC)

Khi nào KHÔNG cần?

  • pub.dev có plugin sẵn — dùng plugin
  • Camera, location, Firebase — đều có plugins
  • HTTP, local storage — đã có Dart packages

Ví dụ Platform Channel

// Dart side
static const channel =
  MethodChannel('com.cmc/battery');

Future<int> getBatteryLevel() async {
  final level =
    await channel.invokeMethod('getBattery');
  return level;
}

// iOS (Swift) side
FlutterMethodChannel(
  "com.cmc/battery",
  handler: (call, result) {
    if call.method == "getBattery" {
      result(UIDevice.current.batteryLevel)
    }
  }
)

MethodChannel = synchronous call.
EventChannel = streaming data.
BasicMessageChannel = bi-directional messaging.

Layer responsibilities

Domain (innermost)

Entities = pure Dart, no dependencies. Usecases = single business logic. Repository interfaces = contracts.

Data (middle)

Models = entities + JSON. DataSources = API calls hoặc DB. Repository implementation = implements domain interface.

Presentation (outermost)

Providers = state management. Screens = pages composed of widgets. Widgets = reusable UI. Không có business logic.

Dependency Rule

Inner layers không biết outer layers tồn tại. Domain ← Data ← Presentation. Dễ test, dễ thay tech stack.

Model & Provider

class User {
  final String name;
  final String email;
  User({required this.name,
       required this.email});

class UserProvider
    extends ChangeNotifier {
  List<User> _users = [];
  List<User> get users => _users;

  bool _isLoading = false;
  bool get isLoading => _isLoading;

  Future<void> fetchUsers() async {
    _isLoading = true;
    notifyListeners();

    _users = await api.getUsers();
    _isLoading = false;
    notifyListeners();
  }
}

RIVERPOD — STATE MANAGEMENT THẾ HỆ MỚI

Tại sao Riverpod?

Compile-time safety

Lỗi được phát hiện lúc compile, không phải runtime. ref.watch() type-safe, không null pointer crash.

Provider hell solved

Nested Provider được flatten. Provider override dễ dàng. Mock trong test không cần ProviderInjection.

Code generation

Riverpod 2.0 với @riverpod_annotation: chỉ cần khai báo, code được generate tự động. flutter pub run build_runner build.

Riverpod code example

// Định nghĩa Provider
@riverpod
Future<List<User>> users(UsersRef ref) async {
  return api.getUsers();
}

// Trong Widget
@riverpod
class UserList extends _$UserList {
  @override
  Future<List<User>> build() => ref.watch(
    usersProvider.future,
  );

  Future<void> refresh() async {
    invalidate(usersProvider);
  }
}

"Riverpod 2.0 + code generation = Flutter state management tương lai. Google dùng trong Google Fonts, Flutter inspect."

FLUTTER NAVIGATION — GO_ROUTER

Tại sao go_router?

Navigator 2.0 declarative

Declarative routing — định nghĩa routes bằng code, không phải imperative push/pop. URL-based navigation.

Deep linking built-in

URL scheme tự động: myapp://home, https://myapp.com/home. iOS universal links, Android app links.

Redirect logic

Authentication redirect: chưa login → redirect về login page. Role-based routing: admin → admin panel.

go_router code example

final router = GoRouter(
  initialLocation: '/',
  redirect: (context, state) {
    final isLoggedIn =
      ref.read(authProvider).isLoggedIn;
    final isLoginRoute =
      state.matchedLocation == '/login';
    if (!isLoggedIn && !isLoginRoute) {
      return '/login';
    }
    return null;
  },
  routes: [
    GoRoute(path: '/', builder: (_, __)
        => HomeScreen()),

ERROR HANDLING — RESULTTYPE TRONG FLUTTER

Result type pattern

// Định nghĩa Result
sealed class Result<T> {
  const Result();
}

final class Success<T>
    extends Result<T> {
  const Success(this.value);
  final T value;
}

final class Failure<T>
    extends Result<T> {
  const Failure(this.exception);
  final Exception exception;
}

// Sử dụng
Future<Result<List<User>>> getUsers() async {
  try {
    final data = await api.getUsers();
    return Success(data);
  } on DioException catch (e) {
    return Failure(NetworkException(e));
  } on Exception catch (e) {
    return Failure(e);
  }
}

Xử lý trong Widget

final result =
    await userRepository.getUsers();

switch (result) {
  case Success(data: final users):
    return UserListView(users: users);
  case Failure(exception: final err):
    return ErrorView(
      message: err.toString(),
      onRetry: () => fetchUsers(),
    );
}

Tại sao không dùng try-catch trực tiếp?

Result type: explicit error handling, compile-time safety. try-catch: implicit, easy to forget, nested catch blocks.

Flutter best practice

Dùng Either type (functional package) hoặc sealed class Result. Không bao giờ để unhandled exception trong production app.

CACHING STRATEGY — OFFLINE-FIRST APPROACH

Caching layers

1

Memory Cache

LRU cache (flutter_cache_manager). Giữ data trong memory khi app đang chạy. Tốc độ nhanh nhất, dung lượng nhỏ.

2

Disk Cache

SharedPreferences (key-value), Hive (NoSQL), SQLite (relational). Persist data khi app tắt. offline-first data.

3

Network (Remote)

API server. Chỉ gọi khi cache stale hoặc không có trong local. Implement stale-while-revalidate pattern.

Offline-first pattern

Future<List<User>> getUsers(
    {bool forceRefresh = false}) async {
  // 1. Check memory cache first
  if (!forceRefresh &&
      memoryCache.hasValidData) {
    return memoryCache.getUsers();
  }

  // 2. Check disk cache
  final diskData = await hiveDb.getUsers();
  if (diskData != null) {
    // Show cached data immediately
    scheduleMicrotask(() =>
        refreshFromNetwork());
    return diskData;
  }

  // 3. Fetch from network
  final networkData = await api.getUsers();
  await hiveDb.saveUsers(networkData);
  return networkData;
}

      return Success(User.fromJson(response.data));
    } on DioException catch (e) {
      return Failure(_handleError(e));
    }
  }

  Future<Result<User>> updateUser(
      String id, Map<String, dynamic> data) async {
    try {
      final response =
          await _dio.put('/users/\$id', data: data);
      return Success(User.fromJson(response.data));
    } on DioException catch (e) {
      return Failure(_handleError(e));
    }
  }

Xu hướng sắp tới

WASM — WebAssembly

Flutter web → WASM compilation. Performance gần bằng native. Flutter 3.22+ stable WASM output. 5-10x performance improvement.

Impeller everywhere

Impeller thay thế Skia trên cả Android (Flutter 3.22+). Loại bỏ shader compilation jank — startup nhanh hơn 50%.

Serverpod — Full-stack Dart

Backend viết bằng Dart. Generated type-safe API client. Severless deployment lên AWS/Google Cloud.

Rust + Flutter (FFI)

ffi gọi Rust từ Dart. Performance-critical code viết bằng Rust. ffigen auto-generation bindings.

Ambient computing
