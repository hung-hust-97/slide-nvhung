ĐỒNG BỘ VS BẤT ĐỒNG BỘ

Synchronous (Đồng bộ)

Code Dart chạy trên 1 thread, thực thi từng câu lệnh một.

Nếu 1 khối code chặn thread (đọc file, gọi API), toàn bộ ứng dụng sẽ bị treo.

void main() {
  print("Start processing");
  processData(); // Chặn!
  print("End");
}

Asynchronous (Bất đồng bộ)

Khi 1 method đang làm việc, khối code khác vẫn được thực thi. Cảm giác như đa luồng (thực ra vẫn là 1 thread).

Dart dùng Future<T> và từ khóa async/await.

void main() async {
  print("Start");
  await fetchData();
  print("Done!");
}

FUTURE<T> TRONG DART

Future<T> là object đại diện cho một giá trị sẽ được cung cấp trong tương lai — tức method trả về kết quả không tức thì mà sau một khoảng thời gian tính toán.

Đặc điểm

  • Method trả về Future<T> không cung cấp kết quả ngay lập tức
  • Kết quả được "delivery" khi computation hoàn tất
  • Dùng cho: gọi API, đọc file, database query, network request
  • Non-blocking — ứng dụng tiếp tục chạy trong khi chờ

Future<T> — kết quả trong tương lai
Nguồn: dart.dev

ASYNC VÀ AWAIT

Từ khóa async

Function được khai báo với từ khóa async sau dấu (). Object trả về luôn là Future<T>.

Future<void> myAsyncFunction() async {
  // Asynchronous operations here
}

Từ khóa await

Dùng await để chờ expression hoàn thành trước khi thực thi dòng tiếp theo trong function.

await expression;

Ví dụ thực tế

Future<void> fetchData() async {
  print("Starting data fetch...");
  await Future.delayed(Duration(seconds: 2));
  print("Data has been fetched!");
}

void main() {
  print("Program started");
  fetchData(); // Không chặn!
  print("Program ended");
}

Output: Program started → Program ended → Starting... → Data fetched!

API Call Pattern

Error Handling với try-catch

Future<User> login(String email, String password) async {
  try {
    var response = await authService.login(email, password);

  }
}

OOP TRONG DART — 5 NGUYÊN TẮC

Objects & Classes

Class Dart chứa methods, fields và static members. Mọi thứ đều là object — bao gồm cả số và null.

Encapsulation

Ẩn dữ liệu nội bộ, chỉ cho phép truy cập qua methods (getters/setters). Dùng _ prefix cho private fields.

Inheritance

Class kế thừa trực tiếp hoặc gián tiếp từ Object. Dart chỉ hỗ trợ single inheritance. Dùng mixins để thừa kế behavior.

Abstraction

Ẩn chi tiết implementation, chỉ expose functionality cần thiết. Dùng abstract class hoặc interface.

Polymorphism

Object có thể nhận nhiều form qua method overriding. Dart cho phép overriding method nhưng không cho phép overloading.

CLASS, CONSTRUCTOR VÀ METHODS

Ví dụ: Class Product

class Product {
  String manufacture = '';
  String name = '';
  var price;
  int quantity;

  // Constructor
  Product(var price, {int quantity = 0}) {
    this.price = price;
    this.quantity = quantity;
  }

  // Method
  double calculateTotal() {

  }

void main() {
  var p = Product(29.99, quantity: 3);
  var total = p.calculateTotal();
  print("Tổng: \$$total");
  // Output: Tổng: $89.97
}

  • Parameterized Constructor — có tham số
  • Named Constructor — Product.fromJson()

GETTER VÀ SETTER

Encapsulation với Getter/Setter

Dùng get trước method không tham số để định nghĩa Getter, và set trước method có 1 tham số để định nghĩa Setter.

class BankAccount {
  double _balance = 0.0;

  // Getter
  double get balance => _balance;

  // Setter cho nạp tiền
  set deposit(double amount) {
    if (amount > 0) {
      _balance += amount;
    }
  }
}

Sử dụng

void main() {
  var account = BankAccount();
  account.deposit = 1000.0;
  print(account.balance);
  // Output: 1000.0

  account.deposit = -50.0; // Bị từ chối!
  print(account.balance);
  // Still: 1000.0
}

Tại sao cần Getter/Setter?

Kiểm soát truy cập, validate dữ liệu, bảo vệ dữ liệu internal — nguyên tắc Encapsulation trong OOP.

KẾ THỪA TRONG DART

Từ khóa quan trọng

  • extends — kế thừa từ class cha
  • super — truy cập dữ liệu/thuộc tính cha
  • @override — ghi đè method của cha
  • this — tham chiếu đến object hiện tại

class Animal {
  String name;
  Animal(this.name);
  void makeSound() {
    print("$name makes a sound.");
  }
}

class Dog extends Animal {
  Dog(String name) : super(name);
  @override
  void makeSound() {
    print("$name barks: Woof! Woof!");
  }
}

Ví dụ sử dụng

void main() {
  var dog = Dog("Buddy");
  dog.makeSound();
  // Output: Buddy barks: Woof! Woof!

  var animal = Animal("Generic");
  animal.makeSound();
  // Output: Generic makes a sound.
}

Lưu ý quan trọng

Dart chỉ hỗ trợ single inheritance (1 class chỉ extends 1 class cha). Dùng mixins để thừa kế nhiều behavior.

CASCADE OPERATOR, ABSTRACT CLASS VÀ INTERFACE

Cascade Operator (..)

Thay vì viết object nhiều lần, dùng .. để gọi liên tiếp các method.

var person = Person()
  ..name = "Lan"
  ..age = 25
  ..introduce();

Abstract Class

Không thể instantiate trực tiếp. Chứa abstract methods (không có implementation).

abstract class B {
  void displayInfo(); // Abstract
}

Interface (implements)

Class implements một interface phải định nghĩa TẤT CẢ methods và properties của interface đó.

class Student implements Person {
  @override
  String name = '';
  @override
  void displayInfo() {
    print("Name: $name");
  }
}

MIXINS TRONG DART

Khái niệm Mixin

Mixin là class không dùng trực tiếp để tạo object. Nó cung cấp methods và properties để tái sử dụng trong các class khác.

Dùng từ khóa with để áp dụng mixin vào class.

mixin Logger {
  void log(String message) {
    print("Log: $message");
  }
}

Ví dụ đầy đủ

class Service {
  void execute() {
    print("Executing service...");
  }
}

class ServiceLogger extends Service with Logger {
  void doSomething() {
    log("Doing something important...");
  }
}

void main() {
  var s = ServiceLogger();
  s.execute();
  s.doSomething();
}

Output: Executing service... → Log: Doing something important...

CALLABLE CLASSES

Class như Function

Class Dart có thể hoạt động như function — có thể được gọi, nhận arguments và trả về kết quả.

Method call() là method đặc biệt — bất kỳ class nào định nghĩa nó có thể hoạt động như một function Dart bình thường.

class MyCallable {
  void call(String message) {
    print("You called me with: $message");
  }
}

Sử dụng Callable Class

void main() {
  var obj = MyCallable();
  obj("Hello!"); // Gọi như function
  // Output: You called me with: Hello!
}

Ứng dụng thực tế

Dùng callable classes để tạo function objects với state, callback handlers, hoặc API clients trong Flutter. Kết hợp với typedef để define function type.

NAMED CONSTRUCTORS VÀ FACTORY

Named Constructor

Cho phép tạo nhiều cách khởi tạo khác nhau cho cùng 1 class.

class Point {
  double x, y;

  // Named constructor
  Point.origin()
    : x = 0, y = 0;

  Point.custom(this.x, this.y);
}

Const Constructor

Constructor với const tạo object compile-time constant.

class ImmutablePoint {
  final double x, y;
  const ImmutablePoint(this.x, this.y);
}
const p = ImmutablePoint(3, 4);

Factory Constructor

Kiểm soát việc khởi tạo object — có thể trả về instance đã có sẵn hoặc subclass.

class Logger {
  static final _cache = <String, Logger>{};

  factory Logger(String name) {
    return _cache.putIfAbsent(
      name, () => Logger._internal(name));
  }
  Logger._internal(this.name);
}

Khi nào dùng Factory?

Singleton pattern, cache instances, khởi tạo có điều kiện, hoặc trả về subclass.

CONST VÀ STATIC TRONG CLASS

Const Constructor

Constructor với const tạo object compile-time constant — tất cả fields phải là final.

class ImmutablePoint {
  final double x, y;

  const ImmutablePoint(this.x, this.y);
}

const p = ImmutablePoint(3, 4);

Lợi ích

Const objects được cache bởi Dart VM — tiết kiệm memory, so sánh bằng identity (cùng 1 object).

Static Members

Thuộc về class, không phải instance. Gọi qua ClassName.member.

class MathUtils {
  static const pi = 3.14159;

  static double circleArea(double r) {
    return pi * r * r;
  }
}

void main() {
  print(MathUtils.circleArea(5));
}

Static vs Instance

Static: gọi không cần tạo object. Instance: gọi qua variable. Static không truy cập this.

KẾ THỪA SÂU — SUPER VÀ OVERRIDE

Constructor trong Inheritance

Constructor của subclass phải gọi constructor của parent qua super.

class Vehicle {
  String brand;
  Vehicle(this.brand);
}

class Car extends Vehicle {
  int doors;
  // Gọi super constructor
  Car(String brand, this.doors)
    : super(brand);
}

Super để gọi Parent Method

class Parent {
  void greet() {
    print("Hello!");
  }
}

class Child extends Parent {
  @override
  void greet() {
    super.greet();
    print("And welcome!");
  }
}

Quy tắc Override

Dùng @override annotation — Dart sẽ báo lỗi nếu method không tồn tại ở parent.

ABSTRACT CLASS — ĐỊNH NGHĨA VÀ VÍ DỤ

Khái niệm

Abstract class là blueprint cho các class khác kế thừa. Không thể instantiate trực tiếp.

Có thể chứa:

  • Abstract methods — không có body, subclass phải implement
  • Concrete methods — có body, subclass có thể override
  • Fields và constructors

So sánh

Abstract class ≠ Interface: abstract class có thể có shared implementation, interface chỉ define contract.

Ví dụ đầy đủ

abstract class Shape {
  String color;
  Shape(this.color);

  // Abstract method
  double area();

  // Concrete method
  void describe() {
    print("Color: $color");
  }
}

class Circle extends Shape {
  double radius;
  Circle(String color, this.radius)
    : super(color);
  @override
  double area() => 3.14 * radius * radius;
}

INTERFACE — IMPLEMENTS TRONG DART

Khái niệm Interface

Interface là contract — class implement interface phải implement TẤT CẢ methods và properties của nó.

Trong Dart, mọi class đều là interface. Dùng implements để implement.

Khác với Abstract class

Interface không có implementation mặc định. Subclass phải định nghĩa lại mọi thứ.

Ví dụ

abstract class Printable {
  void printInfo(); // Contract
}

class Report implements Printable {
  String title = '';
  DateTime date = DateTime.now();

  @override
  void printInfo() {
    print("$title - $date");
  }
}

class Invoice implements Printable {
  double amount = 0;

  @override
  void printInfo() {
    print("Invoice: \$$amount");
  }
}

MIXINS NÂNG CAO — WITH CLAUSE

Tại sao cần Mixins?

Dart chỉ hỗ trợ single inheritance (1 class extends 1 class). Mixins cho phép kế thừa behavior từ nhiều nguồn.

mixin Flyer {
  void fly() => print("Flying!");
}

mixin Swimmer {
  void swim() => print("Swimming!");
}

class Duck extends Animal with Flyer, Swimmer {}

Mixin on Type

Dùng on để giới hạn mixin chỉ áp dụng cho class nào đó.

mixin Piloting on Aircraft {
  void pilot() => print("Piloting...");
}

// CHỉ áp dụng cho subclass của Aircraft
class Helicopter extends Aircraft with Piloting {}

CALLABLE CLASSES — THỰC HÀNH

Khai báo Callable

Class có method call() có thể được gọi như function thông thường.

class TaxCalculator {
  final double rate;
  TaxCalculator(this.rate);

  double call(double amount) {
    return amount + (amount * rate);
  }
}

Sử dụng

void main() {
  var tax = TaxCalculator(0.1);
  print(tax(1000)); // 1100.0
  print(tax(2500)); // 2750.0

  // Hoặc gọi trực tiếp
  var result = TaxCalculator(0.08)(500);
  print(result); // 540.0
}

Ứng dụng

Tạo function objects với state, validation callbacks, hoặc strategy pattern trong Flutter widgets.

EXTENSION METHODS

Thêm methods cho class có sẵn

Extension methods cho phép thêm functionality cho class mà không cần kế thừa hoặc sửa source code.

extension StringExtensions on String {
  bool get isEmail {
    return this.contains('@');
  }

  String capitalize() {
    return this[0].toUpperCase()
      + substring(1);
  }
}

Sử dụng

void main() {
  "hello".capitalize();

  // true

  "world".capitalize().isEmail;
  // false
}

Khi nào dùng?

Thêm utility methods cho String, int, List của thư viện bên thứ 3 hoặc Dart SDK mà không thể sửa.

ENUM TRONG DART

Enum cơ bản

Enum định nghĩa tập hợp cố định các giá trị. Dart enums là classes có thể có methods.

  for (var v in Priority.values) {

  }

Enum với Properties và Methods

enum Status {
  pending(0, "Đang chờ"),
  active(1, "Đang hoạt động"),
  completed(2, "Hoàn thành");

  final int code;
  final String label;
  const Status(this.code, this.label);
}

void main() {
  print(Status.active.label);
  // "Đang hoạt động"
}

Enum có thể implements interfaces, mix with mixins, và có static members — đủ để thay thế sealed classes trong nhiều trường hợp.

SEALED CLASSES (DART 3.0)

Khái niệm

Sealed class là abstract class nhưng các subclasses bị giới hạn trong cùng file. Dart biết trước tất cả subclasses — enable exhaustive switch expressions.

sealed class Result {}

class Success extends Result {
  final dynamic data;
  Success(this.data);
}

class Error extends Result {
  final String message;
  Error(this.message);
}

Exhaustive Switch

Dart yêu cầu xử lý tất cả cases — compiler báo lỗi nếu thiếu case.

String describe(Result r) => switch (r) {
  Success(:final data) => "Data: $data",
  Error(:final message) => "Error: $message",
};

✨ XU HƯỚNG HIỆN ĐẠI

Sealed classes + records (Dart 3.0) là bộ đôi mạnh mẽ thay thế union types, dùng phổ biến trong BLoC states, API responses, và form validation.

ASYNC/AWAIT — BÀI TẬP API CALL

Yêu cầu

Xây dựng function fetchUserProfile() gọi API, xử lý lỗi, và trả về User object.

1

Tạo class User với named constructor fromJson()

2

Viết fetchUserProfile(String id) với try-catch-finally

3

Xử lý 3 loại lỗi: network, timeout, server error

Future<User> fetchUserProfile(String id) async {

PATTERN MATCHING VỚI SWITCH (DART 3.0)

Switch Expressions

Switch trong Dart 3.0 là expression — trả về giá trị, có thể gán cho biến.

String describe(Object obj) => switch (obj) {
  int i when i > 0 => 'Positive int: $i',
  int i => 'Negative int: $i',
  String s => 'String: $s',
  _ => 'Unknown type',
};

Ưu điểm

Exhaustive (yêu cầu xử lý mọi case), có guard clause (when), ngắn gọn hơn if-else chain.

  _ => 'Unknown',

CLASS MODIFIERS (DART 3.0)

final class

Không thể extend hoặc implement. Dùng khi class đã hoàn chỉnh, không muốn bị kế thừa.

base class

GENERICS TRONG DART

Khái niệm

// Không generics — mất type safety

  T? get item => _item;
  void set item(T? val) { _item = val; }
}

var intBox = Box<int>();
intBox.item = 42; // ✅ type safe

Generics Constraints

Giới hạn T phải implement một interface nhất định.

// T phải implement Comparable
T max<T extends Comparable<T>>(T a, T b) {
  return a.compareTo(b) > 0 ? a : b;
}

void main() {
  print(max(3, 5)); // 5
  print(max('apple', 'banana')); // banana
}

Generic Collections

SOLID PRINCIPLES TRONG DART

S — Single Responsibility

Mỗi class có một lý do duy nhất để thay đổi. Tách biệt responsibilities.

Bad: class vừa tính lương, vừa xuất PDF, vừa gửi email.

Good: PayrollCalculator + PdfExporter + EmailService riêng biệt.

O — Open/Closed

Class mở để mở rộng, đóng để sửa đổi. Dùng abstract class, interface, extension.

Good: abstract class Shape + Circle extends Shape, Rectangle extends Shape.

L — Liskov Substitution

Subclass có thể thay thế parent mà không thay đổi behavior. Override method phải tương thích.

Example: Square extends Rectangle — LSP violation vì setWidth≠setHeight.

I — Interface Segregation

Nhiều interface nhỏ tốt hơn 1 interface lớn. Class chỉ implement những gì cần.

Good: Walkable, Flyable, Swimmable riêng — thay vì 1 Animal interface lớn.

D — Dependency Inversion

Phụ thuộc vào abstraction, không phải concrete class. Dùng inject (DI pattern).

Example: Constructor nhận Repository<T>, không biết cụ thể là MySQL hay Firebase.

SOLID — MINH HỌA TRONG DART

Dependency Inversion

Đúng: phụ thuộc abstraction (Repository), không concrete class.

// Abstraction
abstract class Repository<T> {
  Future<List<T>> findAll();
  Future<T?> findById(String id);
}

class UserRepository implements Repository<User> {
  final _db = FirebaseFirestore.instance;
  Future<List<User>> findAll() async { ... }
  Future<User?> findById(String id) async { ... }
}

  final Repository<User> _repo; // injected
  UserService(this._repo);
}

Interface Segregation

Tách nhỏ interface — class chỉ implement những gì cần.

// THAY VÌ: 1 interface lớn
abstract class Animal { void fly(); void run(); void swim(); }

// ĐÚNG: Nhiều interface nhỏ
abstract class Flyable { void fly(); }
abstract class Walkable { void walk(); }
abstract class Swimmable { void swim(); }

class Dolphin implements Swimmable { ... }
class Dog implements Walkable { ... }
class Duck implements Walkable, Flyable, Swimmable { ... }

Singleton

Factory Pattern

class Transport {
  factory Transport(String type) {
    switch (type) {
      case 'car': return Car();

      default: throw ArgumentError();
    }

Observer / Listener

class Observable<T> {
  T? _value;
  final _listeners = <void Function(T?)>[];

  T? get value => _value;

  void set value(T? v) {
    _value = v;
    for (var l in _listeners) l(v);
  }

  void listen(void Function(T?) fn) {
    _listeners.add(fn);
  }
}

Singleton: Config, Logger. Factory: platform-specific objects. Observer: state management, event buses.
