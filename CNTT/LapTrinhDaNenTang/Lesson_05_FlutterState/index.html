DECLARATIVE UI TRONG FLUTTER

Flutter tiếp cận rendering UI theo cách declarative (khai báo). Widgets khai báo appearance dựa trên input configuration (properties) và internal state.

Ưu điểm của Declarative UI

  • UI được rebuild khi state thay đổi — đảm bảo hiển thị nhất quán
  • Developer chỉ cần mô tả UI nên trông như thế nào ở một state cụ thể
  • Framework tự động xử lý việc cập nhật DOM/virtual tree
  • Dễ dàng debug, predict và test
✨ XU HƯỚNG HIỆN ĐẠI

Declarative UI đang là xu hướng: SwiftUI, Jetpack Compose, Flutter đều dùng cách tiếp cận này — thay thế cho Android XML layouts truyền thống.

STATELESS WIDGET

Định nghĩa

StatelessWidget là widget hoàn toàn bất biến — state không bao giờ thay đổi sau khi widget được tạo.

Phù hợp cho: biểu tượng, text tĩnh, hình ảnh tĩnh, giao diện không thay đổi.

Nên ưu tiên dùng!

Cải thiện hiệu năng — Flutter khuyến khích dùng StatelessWidget cho phần lớn UI.

Ví dụ mã nguồn

class MyStaticText extends StatelessWidget {
  final String text;
  MyStaticText({Key key, @required this.text})
    : super(key: key);

  @override
  Widget build(BuildContext context) {
    return Text(text, style: TextStyle(fontSize: 20.0));
  }
}

Không có biến state (thường nằm trong State class riêng).

STATEFUL WIDGET

Định nghĩa

StatefulWidget là widget giữ state data có thể thay đổi trong vòng đời widget.

3 lý do dùng StatefulWidget

  • Widget cần thay đổi data trong vòng đời
  • Widget cần khởi tạo khi được tạo
  • Widget cần giải phóng tài nguyên khi kết thúc

Vì sao cần tách?

StatefulWidget class immutable nhưng State object mutable — tách riêng để quản lý lifecycle.

Ví dụ: Counter Widget

class MyCounter extends StatefulWidget {
  @override
  _MyCounterState createState() => _MyCounterState();
}

class _MyCounterState extends State<MyCounter> {
  int _counter = 0;

  void _increment() {
    setState(() { _counter++; });
  }

  @override
  Widget build(BuildContext context) {
    return Column(children: [
      Text('Count: $_counter'),
      ElevatedButton(onPressed: _increment, child: Text('+'))
    ]);
  }
}

INHERITED WIDGET

Vai trò của InheritedWidget

InheritedWidget là widget đặc biệt trong Flutter, cho phép truyền data hiệu quả xuống widget tree.

  • Có thể cung cấp mọi loại data cho tất cả descendants trong widget tree
  • Data truyền ngầm định, không cần pass qua constructor
  • Khi data thay đổi, chỉ descendant widgets đang lắng nghe mới rebuild — tối ưu hiệu năng

Khi nào dùng?

InheritedWidget đặc biệt hữu ích cho quản lý và chia sẻ state/data qua một phần lớn của widget tree.

Ví dụ sử dụng phổ biến

App Themes

ThemeData được truyền qua InheritedTheme

Provider / BLoC

State management libraries dựa trên InheritedWidget

Authentication State

Truyền trạng thái đăng nhập xuống toàn bộ app

Locale / Localization

Ngôn ngữ ứng dụng được truyền ngầm

STATE MANAGEMENT LÀ GÌ?

State management là cách theo dõi và xử lý thay đổi dữ liệu trong ứng dụng, đảm bảo UI phản ánh đúng trạng thái hiện tại của dữ liệu.

Các câu hỏi State Management trả lời

1

Khi user nhấn refresh?

Server data thay đổi → state cập nhật → UI rebuild

2

Khi server cập nhật data?

Real-time update → state thay đổi → tất cả widgets liên quan rebuild

3

Làm sao components biết state hiện tại?

Centralized state store → các widgets subscribe → nhận notification khi state thay đổi

PROVIDER

Mô tả

Provider là giải pháp quản lý state rất phổ biến trong Flutter. Cho phép tạo và quản lý providers để lưu trữ state, giúp widgets lắng nghe thay đổi.

Ưu điểm

  • Dễ sử dụng, được áp dụng rộng rãi
  • Hỗ trợ chia sẻ state giữa các widgets
  • Tích hợp tốt với Flutter, dễ test

Nhược điểm

  • Cần hiểu ChangeNotifier và Consumer
  • Có thể phức tạp với app lớn

Ví dụ cơ bản

// 1. ChangeNotifier
class CartModel extends ChangeNotifier {
  final List<Item> _items = [];
  List<Item> get items => List.unmodifiable(_items);
  void add(Item item) { _items.add(item); notifyListeners(); }
}

// 2. Cung cấp provider
ChangeNotifierProvider(
  create: (context) => CartModel(),
  child: MyApp(),
);

// 3. Sử dụng
Consumer<CartModel>(
  builder: (context, cart, child) =>
    Text('Items: ${cart.items.length}'),
);

GETX

Mô tả

GetX là thư viện quản lý state mạnh mẽ và nhẹ cho Flutter. Cung cấp cách đơn giản và hiệu quả để xử lý navigation, state và dependency injection.

Ưu điểm

  • Hiệu năng cao, nhẹ, dễ dùng
  • Xử lý state và routing với code tối thiểu
  • Hỗ trợ dependency injection rõ ràng

Nhược điểm

  • Khó bảo trì trong app lớn
  • Cộng đồng nhỏ hơn Provider và Riverpod

Ví dụ sử dụng

// Controller
class CounterController extends GetxController {
  var count = 0.obs; // Observable
  void increment() => count++;
}

// Sử dụng trong Widget
GetBuilder<CounterController>(
  init: CounterController(),
  builder: (controller) =>
    Text('Count: ${controller.count}'),
);

// Gọi từ bất kỳ đâu
Get.find<CounterController>().increment();

GetX phổ biến ở Việt Nam và Trung Quốc — nhiều template trên GitHub dùng GetX. Nhưng enterprise app quốc tế ưa Riverpod hơn.

RIVERPOD

Mô tả

Riverpod là thư viện quản lý state giống Provider nhưng cải tiến hơn. Sử dụng unidirectional data flow, giảm vấn đề về readability, testability và performance.

Ưu điểm

  • Giảm runtime errors — phát hiện lỗi at compile time
  • Không phụ thuộc BuildContext, dễ test
  • Hiệu năng và code clarity tốt hơn

Nhược điểm

  • Mới hơn Provider, cần học syntax

Ví dụ

// Provider đơn giản
final counterProvider = StateProvider((ref) => 0);

// ConsumerWidget
class CounterWidget extends ConsumerWidget {
  @override
  Widget build(BuildContext context, WidgetRef ref) {
    final count = ref.watch(counterProvider);
    return Column(children: [
      Text('Count: $count'),
      ElevatedButton(
        onPressed: () => ref.read(counterProvider.notifier).state++,
        child: Text('+'),
      ),
    ]);
  }
}

REDUX

Mô tả

Redux là mô hình quản lý state dựa trên nguyên tắc unidirectional data flow. Cung cấp sự phân tách rõ ràng giữa UI và business logic.

Ưu điểm

  • Quản lý state rõ ràng, phân tách UI/logic
  • Dễ test và debug — identify bugs hiệu quả
  • Time-travel debugging

Nhược điểm

  • Phức tạp hơn Provider/Riverpod
  • Overkill cho app nhỏ

Redux Flow

1

Action

Intent gửi đến store (VD: ADD_ITEM, REMOVE_ITEM)

2

Reducer

Function nhận action + current state → trả về new state

3

Store

Chứa state tree của ứng dụng. Thông báo cho subscribers khi state thay đổi.

BLoC — BUSINESS LOGIC COMPONENT

Mô tả

BLoC viết tắt của Business Logic Component — pattern do Google giới thiệu, tách biệt hoàn toàn business logic khỏi UI.

"BLoC connects Events (từ UI) to States (cho UI)" — Brian Egan, 2018

Ưu điểm

  • Tách biệt UI hoàn toàn với logic
  • Dễ test — business logic không phụ thuộc widget
  • Code có thể reuse ở nhiều UI

Nhược điểm

  • Boilerplate code nhiều hơn Provider
  • Cần học thêm khái niệm Streams

Cấu trúc BLoC

1

Events

Trigger từ UI: LoadData, AddItem, DeleteItem, UpdateQuantity

2

BLoC

Nhận event → xử lý logic → phát state mới

3

States

Trạng thái kết quả: Initial, Loading, Loaded, Error

4

UI

BlocBuilder lắng nghe state → rebuild UI tương ứng

THỰC HÀNH — SHOPPING CART VỚI PROVIDER

Yêu cầu app

  • Danh sách sản phẩm (tên, giá, hình)
  • Nhấn "Thêm vào giỏ" → cập nhật giỏ hàng
  • Hiển thị tổng số lượng và tổng tiền
  • Nhấn "Xóa" → bỏ sản phẩm khỏi giỏ

Các bước thực hiện

1

Tạo class Item (id, name, price, image)

2

Tạo CartModel extends ChangeNotifier

3

Bọc ChangeNotifierProvider ở root

CartModel — Code đầy đủ

class CartModel extends ChangeNotifier {
  final List<Item> _items = [];

  List<Item> get items => _items.toList();
  int get totalItems => _items.length;
  double get totalPrice =>
    _items.fold(0, (sum, item) => sum + item.price);

  void addItem(Item item) {
    _items.add(item);
    notifyListeners();
  }

  void removeItem(int index) {
    _items.removeAt(index);
    notifyListeners();
  }
}

THỰC HÀNH — SHOPPING CART VỚI RIVERPOD

Provider Definitions

// Item model
class Item {
  final int id; final String name;
  final double price;
  const Item(this.id, this.name, this.price);
}

// StateNotifier
class CartNotifier extends StateNotifier<List<Item>> {
  CartNotifier() : super([]);

  void add(Item item) { state = [...state, item]; }
  void remove(int id) {
    state = state.where((i) => i.id != id).toList();
  }
}

// Provider
final cartProvider = StateNotifierProvider<
  CartNotifier, List<Item>>((ref) => CartNotifier());

        itemCount: products.length,
        itemBuilder: (ctx, i) => ListTile(
          title: Text(products[i].name),
          trailing: IconButton(
            icon: Icon(Icons.add_shopping_cart),
            onPressed: () => ref
              .read(cartProvider.notifier).add(products[i]),
        ),
      ),
    );
  }
}

Lưu ý Riverpod

ref.watch() → auto-rebuild khi state thay đổi. ref.read() → đọc một lần (dùng trong callback).

PROVIDER — context.watch vs context.read vs Consumer

Provider.of + listen

// Đọc state + lắng nghe thay đổi

  context, listen: true);
// Widget rebuild khi cart thay đổi

  context, listen: false);

ANIMATIONS TRONG FLUTTER — ANIMATIONCONTROLLER

Mô tả

AnimationController quản lý animation timeline — xác định giá trị (value) thay đổi theo thời gian.

Các thuộc tính quan trọng

  • duration — thời gian animation (VD: 1 giây)
  • vsync — đồng bộ với refresh rate màn hình (dùng TickerProviderStateMixin)
  • value — giá trị hiện tại (0.0 → 1.0)
  • repeat(), forward(), reverse()

SingleTickerProviderStateMixin

Dùng cho 1 animation controller. TickerProviderStateMixin khi cần nhiều controllers.

Ví dụ: Fade In Animation

class FadeInWidget extends StatefulWidget {
  @override
  _FadeInWidgetState createState() =>
    _FadeInWidgetState();
}

class _FadeInWidgetState
  extends State<FadeInWidget>
  with SingleTickerProviderStateMixin {
  late AnimationController _controller;
  late Animation<double> _fadeAnimation;

  @override
  void initState() {
    super.initState();
    _controller = AnimationController(
      duration: Duration(seconds: 1),
      vsync: this,
    );
    _fadeAnimation =
      Tween(begin: 0.0, end: 1.0)
        .animate(_controller);
    _controller.forward();
  }

  @override
  Widget build(BuildContext context) {
    return FadeTransition(
      opacity: _fadeAnimation,
      child: MyContent(),
    );
  }
}

BEST PRACTICES VÀ PITFALLS THƯỜNG GẶP

setState trong build()

❌ Gọi setState bên trong build() → infinite loop. ✅ Dùng didChangeDependencies() hoặc callback từ parent.

Dispose resources

❌ Quên dispose AnimationController, StreamSubscription, TextEditingController → memory leak. ✅ Luôn override dispose().

Async operations trong build()

❌ Gọi async trong build() → widget chưa ready. ✅ Dùng FutureBuilder hoặc state management.

MediaQuery.of(context) trong initState

❌ Dùng MediaQuery trước build() → null. ✅ Dùng sau widget mounted (inside build() or didChangeDependencies()).

Keys không cần thiết

❌ Thêm Key() cho mọi widget → performance giảm. ✅ Chỉ dùng Key khi cần preserve widget state trong list.

Hardcoded strings

❌ Hardcoded text everywhere → khó i18n. ✅ Dùng flutter_localizations + ARB files.

5 nguyên tắc vàng

1

StatelessWidget trước

Luôn bắt đầu với StatelessWidget. Chỉ dùng StatefulWidget khi thực sự cần thay đổi state.

2

Container queries thay vì MediaQuery

Dùng LayoutBuilder cho responsive layout thay vì hardcoded breakpoints.

3

Null safety từ đầu

Luôn bật null safety, tránh null check rườm rà ở production.

ASYNC / AWAIT VÀ XỬ LÝ LỖI

Mọi network call, database operation đều là asynchronous. Dart dùng Future (kết quả tương lai) và async/await để xử lý bất đồng bộ.

Future + Async/Await

// Async function trả về Future<T>
Future<User> fetchUser(int id) async {
  // Gọi API — tạm dừng cho đến khi xong
  final response = await api.get('/users/$id');
  // Parse JSON
  return User.fromJson(response.data);
}

// Gọi từ UI
void loadUser() async {
  try {
    setState(() => _isLoading = true);
    final user = await fetchUser(1);
    setState(() => _user = user);
  } finally {
    setState(() => _isLoading = false);
  }
}

Xử lý lỗi với try/catch/finally

Future<List<Product>> fetchProducts() async {
  try {
    final response = await api.get('/products');
    return (response.data as List)
      .map((j) => Product.fromJson(j)).toList();

  } on SocketException {
    // Không có internet
    throw NetworkException('Không có kết nối mạng');

  } on TimeoutException {
    throw NetworkException('Server quá chậm');

  } catch (e) {
    // Lỗi không xác định
    throw NetworkException('Lỗi: $e');

  } finally {
    // Luôn chạy — cleanup
    _isLoading = false;
  }
}

Dùng FutureBuilder để render UI dựa trên Future state (loading, data, error).

    return CircularProgressIndicator();
  },
);

State Management: Cubit

// Cubit — đơn giản hơn BLoC
class TodosCubit extends Cubit<TodosState> {
  final TodosRepository _repository;

  TodosCubit(this._repository)
    : super(TodosInitial());

  Future<void> loadTodos() async {
    emit(TodosLoading());
    try {
      final todos = await _repository.getTodos();
      emit(TodosLoaded(todos));
    } catch (e) {
      emit(TodosError(e.toString()));
    }
  }

  Future<void> addTodo(String title) async {
    await _repository.addTodo(Todo(title));
    await loadTodos();
  }
}

Tại sao dùng Cubit thay vì BLoC?

Cubit đơn giản hơn — không cần Events, chỉ gọi methods trực tiếp trên Cubit. Phù hợp cho app có state logic không quá phức tạp.
