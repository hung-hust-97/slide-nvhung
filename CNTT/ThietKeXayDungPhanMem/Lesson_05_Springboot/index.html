JAVA SPRING BOOT LÀ GÌ?

Spring Boot là framework giúp đơn giản hóa và tăng tốc phát triển ứng dụng Java, đặc biệt cho web applications và APIs. [spring.io]

Tính năng chính:

  • Minimal configuration — auto-configuration thay vì XML
  • Embedded server — Tomcat/Jetty tích hợp sẵn
  • Starter dependencies — thêm tính năng bằng 1 dependency
  • Production-ready — health checks, metrics, logging
  • Spring Initializr — tạo project online trong 30 giây

Tại sao chọn Spring Boot?

Ưu điểmChi tiết
NhanhPhát triển nhanh hơn Java EE truyền thống
Tích hợpDễ dàng kết nối DB, messaging, caching
DependencyMaven/Gradle quản lý thư viện tự động
Cộng đồngLớn nhất trong Java ecosystem
StandaloneChạy bằng java -jar, không cần server riêng

Hạn chế: Dependencies làm tăng kích thước ứng dụng; learning curve cho Spring ecosystem rộng lớn.

KIẾN TRÚC SPRING BOOT — MVC

1

Controller (API Layer)

Nhận HTTP request từ client → validate input → gọi Service → trả response (JSON). Annotations: @RestController, @GetMapping, @PostMapping

2

Service (Business Logic)

Xử lý logic nghiệp vụ → gọi Repository → trả kết quả cho Controller. Annotation: @Service

3

Repository (Data Access)

Interface truy cập database → extends JpaRepository → cung cấp CRUD operations. Annotation: @Repository

4

Entity (Domain Model)

Class Java ánh xạ với bảng database → mỗi instance = 1 row. Annotations: @Entity, @Id, @Column

Luồng xử lý: Client → Controller → Service → Repository → Database → Repository → Service → Controller → Client (JSON response)

IOC & DEPENDENCY INJECTION

IoC (Inversion of Control) — đảo ngược điều khiển: thay vì class tự tạo dependencies, container sẽ inject chúng vào. [Martin Fowler]

3 cách inject:

  • Constructor Injection (khuyến nghị) — immutable, dễ test
  • Setter Injection — cho optional dependencies
  • Field Injection — @Autowired trên field (không khuyến nghị)

Lợi ích:

  • Loose coupling — dễ thay đổi implementation
  • Dễ unit test — mock dependencies
  • Code cleaner — tập trung business logic

VD: 3 kiểu Injection

// 1. Constructor Injection (BEST)
@Service
@RequiredArgsConstructor
public class UserService {
  private final UserRepository userRepo;
  // Spring tự inject UserRepository
}

// 2. Setter Injection
@Service
public class UserService {
  private UserRepository userRepo;
  @Autowired
  public void setUserRepo(UserRepository r) {
    this.userRepo = r;
  }
}

// 3. Field Injection (AVOID)
@Service
public class UserService {
  @Autowired
  private UserRepository userRepo;
}

REST LÀ GÌ?

REST (Representational State Transfer) là kiểu kiến trúc để xây dựng web services. [Wikipedia]

Nguyên tắc thiết kế RESTful:

  • Stateless — mỗi request chứa đầy đủ thông tin, server không lưu session
  • Resource-based — mọi thứ là resource, truy cập qua URI
  • HTTP Methods — GET, POST, PUT, DELETE cho CRUD
  • JSON/XML — data format chuẩn
  • Status Codes — 200, 201, 400, 404, 500...
  • Consistent URIs — /api/users, /api/courses/{id}

HTTP Methods:

MethodCRUDVí dụ
GETReadGET /api/users
POSTCreatePOST /api/users
PUTUpdatePUT /api/users/1

ENTITY — ÁNH XẠ DATABASE

Entity đại diện cho 1 bảng trong database. Mỗi instance = 1 row.

Annotations chính:

AnnotationMục đích
@EntityĐánh dấu class là entity
@TableChỉ định tên bảng
@IdPrimary key
@GeneratedValueAuto-increment
@ColumnÁnh xạ cột (name, nullable, unique)
@EnumeratedÁnh xạ enum

VD: Entity User

@Entity
@Table(name = "users")
public class User {

  @Id
  @GeneratedValue(strategy =
    GenerationType.IDENTITY)
  private Long id;

  @Column(nullable = false,
    unique = true, length = 100)
  private String email;

  @Column(nullable = false)
  private String password;

  @Column(name = "full_name")
  private String fullName;

  @Enumerated(EnumType.STRING)
  private Role role;
  // Role = enum {STUDENT, TEACHER, ADMIN}
}

LOMBOK — GIẢM BOILERPLATE CODE

Tại sao cần Getters/Setters?

  • Encapsulation — fields private, truy cập qua methods
  • Framework cần — JPA/Hibernate dùng reflection qua getter/setter
  • Validation — setter có thể thêm validation logic

Không dùng Lombok:

public class User {
  private String email;
  public String getEmail() { return email; }
  public void setEmail(String e) { email = e; }
  // + constructor, toString, equals, hashCode
  // = 50-100 dòng boilerplate!
}

Với Lombok:

@Entity
@Getter
@Setter
@NoArgsConstructor
@AllArgsConstructor
@Builder
public class User {

  @Id @GeneratedValue(strategy =
    GenerationType.IDENTITY)
  private Long id;

  private String email;
  private String password;
  private String fullName;
  private Role role;
}

Lombok Annotations phổ biến:

  • @Getter/@Setter — auto generate
  • @NoArgsConstructor — constructor rỗng
  • @AllArgsConstructor — constructor đầy đủ
  • @Builder — Builder pattern
  • @Data — tổng hợp tất cả

DTO — DATA TRANSFER OBJECT

3 loại data trong Spring Boot:

LoạiMục đíchVD
EntityÁnh xạ DB table, chứa tất cả fieldsUser.java (@Entity)
DTOTruyền dữ liệu qua API, chỉ fields cần thiếtUserDTO.java
Domain ModelBusiness objects, chứa business logicReport, Calculator

Tại sao dùng DTO?

  • Không expose toàn bộ Entity (VD: password)
  • Giảm data truyền tải (chỉ fields cần)
  • Tăng bảo mật (ẩn internal structure)
  • Decouple API contract khỏi DB schema

VD: Entity vs DTO

// Entity — có password, internal fields
@Entity
public class User {
  private Long id;
  private String email;
  private String password;  // KHÔNG expose!
  private String fullName;
  private Role role;
  private LocalDateTime createdAt;
}

// DTO — chỉ fields cần cho API
@Data
public class UserDTO {
  private Long id;
  private String email;
  // KHÔNG có password
  private String fullName;
  private String role;
}

// CreateUserDTO — input cho POST
@Data
public class CreateUserDTO {
  @NotBlank
  private String email;
  @Size(min = 8)
  private String password;
  private String fullName;
}

REPOSITORY — TRUY CẬP DỮ LIỆU

Repository là interface cung cấp CRUD operations cho entities — cầu nối với database.

Extends interfaces:

InterfaceCung cấp
CrudRepositorysave, findById, findAll, delete
JpaRepositoryCRUD + paging + sorting + flush
PagingAndSortingRepositoryCRUD + paging + sorting

Methods có sẵn:

  • save(entity) — insert hoặc update
  • findById(id) — tìm theo ID
  • findAll() — lấy tất cả
  • deleteById(id) — xóa theo ID
  • count() — đếm số lượng

VD: UserRepository

@Repository
public interface UserRepository
    extends JpaRepository<User, Long> {

  // Query by method name
  Optional<User> findByEmail(String email);
  List<User> findByRole(Role role);
  boolean existsByEmail(String email);

  // Custom query
  @Query("SELECT u FROM User u "
    + "WHERE u.fullName LIKE %:name%")
  List<User> searchByName(
    @Param("name") String name);

  // Native SQL
  @Query(value = "SELECT * FROM users "
    + "WHERE role = ?1",
    nativeQuery = true)
  List<User> findByRoleNative(String role);
}

SERVICE — BUSINESS LOGIC

Service chứa logic nghiệp vụ — cầu nối giữa Controller và Repository.

Vai trò:

  • Xử lý business rules
  • Gọi Repository để truy cập DB
  • Giữ Controller đơn giản (thin controller)
  • Transaction management (@Transactional)
  • Validation, transformation, calculations

VD: UserService

@Service
@RequiredArgsConstructor
public class UserService {

  private final UserRepository userRepo;

  public List<User> getAllUsers() {
    return userRepo.findAll();
  }

  public User getUserById(Long id) {
    return userRepo.findById(id)
      .orElseThrow(() ->
        new ResourceNotFoundException(
          "User not found: " + id));
  }

  @Transactional
  public User createUser(UserDTO dto) {
    if (userRepo.existsByEmail(dto.getEmail()))
      throw new DuplicateException("Email exists");
    User user = User.builder()
      .email(dto.getEmail())
      .password(encoder.encode(dto.getPassword()))
      .fullName(dto.getFullName())
      .role(Role.STUDENT)
      .build();
    return userRepo.save(user);
  }
}

CONTROLLER — XỬ LÝ HTTP REQUESTS

Controller xử lý HTTP requests từ client và gửi responses.

Annotations:

AnnotationMục đích
@RestControllerĐánh dấu REST controller
@RequestMappingBase path (/api/users)
@GetMappingHandle GET request
@PostMappingHandle POST request
@PutMappingHandle PUT request
@DeleteMappingHandle DELETE request
@PathVariableLấy param từ URL

VD: UserController

@RestController
@RequestMapping("/api/users")
@RequiredArgsConstructor
public class UserController {

  private final UserService userService;

  @GetMapping
  public List<User> getAll() {
    return userService.getAllUsers();
  }

  @GetMapping("/{id}")
  public User getById(@PathVariable Long id) {
    return userService.getUserById(id);
  }

  @PostMapping
  @ResponseStatus(HttpStatus.CREATED)
  public User create(@RequestBody UserDTO dto) {
    return userService.createUser(dto);
  }

  @DeleteMapping("/{id}")
  @ResponseStatus(HttpStatus.NO_CONTENT)
  public void delete(@PathVariable Long id) {
    userService.deleteUser(id);
  }
}

LUỒNG XỬ LÝ REQUEST

1

Client Request

Client gửi HTTP request (GET, POST...) đến endpoint trong Controller. VD: GET /api/users/1

2

Controller Handling

Controller nhận request, validate input, gọi method tương ứng trong Service. VD: userService.getUserById(1)

3

Service Logic

Service xử lý business logic, gọi Repository. VD: kiểm tra quyền, transform data, gọi userRepo.findById(1)

4

Repository → Database

Repository thực thi SQL query thông qua JPA/Hibernate. VD: SELECT * FROM users WHERE id = 1

5

Response to Client

Kết quả trả ngược: DB → Repository → Service → Controller → JSON Response (200 OK)

EXCEPTION HANDLING TOÀN CỤC

Sử dụng @ControllerAdvice + @ExceptionHandler để xử lý lỗi tập trung, trả response chuẩn cho client.

Lợi ích:

  • Code clean — không try/catch trong từng controller
  • Response format nhất quán
  • Logging tập trung
  • Dễ maintain

Custom Exception:

@ResponseStatus(HttpStatus.NOT_FOUND)
public class ResourceNotFoundException
    extends RuntimeException {
  public ResourceNotFoundException(String msg) {
    super(msg);
  }
}

Global Exception Handler:

@RestControllerAdvice
public class GlobalExceptionHandler {

  @ExceptionHandler(
    ResourceNotFoundException.class)
  public ResponseEntity<ErrorResponse>
      handleNotFound(
        ResourceNotFoundException ex) {
    return ResponseEntity
      .status(HttpStatus.NOT_FOUND)
      .body(new ErrorResponse(
        "NOT_FOUND", ex.getMessage()));
  }

  @ExceptionHandler(
    MethodArgumentNotValidException.class)
  public ResponseEntity<ErrorResponse>
      handleValidation(
        MethodArgumentNotValidException ex) {
    Map<String,String> errors = new HashMap<>();
    ex.getBindingResult().getFieldErrors()
      .forEach(err -> errors.put(
        err.getField(),
        err.getDefaultMessage()));
    return ResponseEntity.badRequest()
      .body(new ErrorResponse(
        "VALIDATION_ERROR", errors));
  }
}

CORS — KẾT NỐI ANGULAR & SPRING BOOT

CORS (Cross-Origin Resource Sharing) — cho phép Angular (port 4200) gọi API Spring Boot (port 8080). Mặc định browser chặn cross-origin requests.

Cách 1: @CrossOrigin annotation

@RestController
@RequestMapping("/api/users")
@CrossOrigin(origins = "http://localhost:4200")
public class UserController { ... }

Cách 2: Global config

@Configuration
public class WebConfig
    implements WebMvcConfigurer {
  @Override
  public void addCorsMappings(
      CorsRegistry registry) {
    registry.addMapping("/api/**")
      .allowedOrigins("http://localhost:4200")
      .allowedMethods("GET","POST","PUT","DELETE")
      .allowedHeaders("*")
      .allowCredentials(true);
  }
}

Cách 3: Spring Security Config

@Bean
public CorsConfigurationSource
    corsConfigurationSource() {
  CorsConfiguration config =
    new CorsConfiguration();
  config.setAllowedOrigins(
    List.of("http://localhost:4200",
      "https://myapp.cmc.vn"));
  config.setAllowedMethods(
    List.of("GET","POST","PUT","DELETE"));
  config.setAllowedHeaders(List.of("*"));
  config.setAllowCredentials(true);

  UrlBasedCorsConfigurationSource source =
    new UrlBasedCorsConfigurationSource();
  source.registerCorsConfiguration(
    "/**", config);
  return source;
}

// Trong SecurityFilterChain
http.cors(cors ->
  cors.configurationSource(
    corsConfigurationSource()));

⚠️ KHÔNG dùng allowedOrigins("*") với allowCredentials(true) — sẽ bị browser block.

BEST PRACTICES SPRING BOOT

Nên làm:

  • Constructor injection — không dùng @Autowired field
  • DTO cho API — không expose Entity trực tiếp
  • @Transactional ở Service layer
  • Validation với @Valid + Bean Validation
  • Global exception handler với @ControllerAdvice
  • application-{profile}.yml — tách config theo môi trường
  • Logging có context — log.info("User {} created", id)
  • Pagination cho list endpoints
  • HTTPS cho production
  • Environment variables cho secrets (KHÔNG commit password)

Tránh:

  • ❌ Field injection (@Autowired field)
  • ❌ Return Entity từ Controller
  • ❌ Logic nghiệp vụ trong Controller
  • ❌ ddl-auto=update ở production
  • ❌ Hardcode credentials trong code
  • ❌ N+1 query problem (dùng @EntityGraph hoặc fetch join)
  • ❌ Catch Exception generic — bắt cụ thể
  • ❌ Synchronized methods — dùng @Async khi cần
  • ❌ Không có test → dễ bug
  • ❌ Dùng Optional làm field hoặc parameter
✨ XU HƯỚNG HIỆN ĐẠI

Spring Boot 3.2+ hỗ trợ Virtual Threads (Project Loom) — xử lý hàng triệu concurrent requests với rất ít memory.
