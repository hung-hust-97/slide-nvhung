WHAT IS JAVA SPRING BOOT?

Spring Boot is a framework that helps simplify and accelerate Java application development, especially for web applications and APIs. [spring.io]

Key features:

  • Minimal configuration — auto-configuration instead of XML
  • Embedded server — built-in Tomcat/Jetty
  • Starter dependencies — add features with a single dependency
  • Production-ready — health checks, metrics, logging
  • Spring Initializr — create a project online in 30 seconds

Why choose Spring Boot?

AdvantageDetails
FastFaster development than traditional Java EE
IntegrationEasy connection to DB, messaging, caching
DependencyMaven/Gradle manages libraries automatically
CommunityLargest in the Java ecosystem
StandaloneRun with java -jar, no separate server needed

Limitations: Dependencies increase application size; learning curve for the vast Spring ecosystem.

SPRING BOOT ARCHITECTURE — MVC

1

Controller (API Layer)

Receives HTTP request from client → validates input → calls Service → returns response (JSON). Annotations: @RestController, @GetMapping, @PostMapping

2

Service (Business Logic)

Processes business logic → calls Repository → returns results to Controller. Annotation: @Service

3

Repository (Data Access)

Interface for database access → extends JpaRepository → provides CRUD operations. Annotation: @Repository

4

Entity (Domain Model)

Java class mapped to a database table → each instance = 1 row. Annotations: @Entity, @Id, @Column

Request flow: Client → Controller → Service → Repository → Database → Repository → Service → Controller → Client (JSON response)

IOC & DEPENDENCY INJECTION

IoC (Inversion of Control) — inverting control: instead of a class creating its own dependencies, the container injects them. [Martin Fowler]

3 ways to inject:

  • Constructor Injection (recommended) — immutable, easy to test
  • Setter Injection — for optional dependencies
  • Field Injection — @Autowired on field (not recommended)

Benefits:

  • Loose coupling — easy to change implementation
  • Easy unit testing — mock dependencies
  • Cleaner code — focus on business logic

Example: 3 Injection types

// 1. Constructor Injection (BEST)
@Service
@RequiredArgsConstructor
public class UserService {
  private final UserRepository userRepo;
  // Spring auto-injects UserRepository
}

// 2. Setter Injection
@Service
public class UserService {
  private UserRepository userRepo;
  @Autowired
  public void setUserRepo(UserRepository r) {
    this.userRepo = r;
  }
}

// 3. Field Injection (AVOID)
@Service
public class UserService {
  @Autowired
  private UserRepository userRepo;
}

Bean lifecycle:

2

5

Destruction

Calls @PreDestroy, DisposableBean

Bean Scopes:

ScopeDescription

prototypeNew instance for each request
request1 instance per HTTP request (web)

WHAT IS REST?

REST (Representational State Transfer) is an architectural style for building web services. [Wikipedia]

RESTful design principles:

  • Stateless — each request contains all necessary information, server does not store sessions
  • Resource-based — everything is a resource, accessed via URI
  • HTTP Methods — GET, POST, PUT, DELETE for CRUD
  • JSON/XML — standard data format
  • Status Codes — 200, 201, 400, 404, 500...
  • Consistent URIs — /api/users, /api/courses/{id}

HTTP Methods:

MethodCRUDExample
GETReadGET /api/users
POSTCreatePOST /api/users
PUTUpdatePUT /api/users/1
DELETEDeleteDELETE /api/users/1
PATCHPartial UpdatePATCH /api/users/1

ENTITY — DATABASE MAPPING

Entity represents a table in the database. Each instance = 1 row.

Key Annotations:

AnnotationPurpose
@EntityMarks class as entity
@TableSpecifies table name
@IdPrimary key
@GeneratedValueAuto-increment
@ColumnColumn mapping (name, nullable, unique)
@EnumeratedEnum mapping

Example: User Entity

@Entity
@Table(name = "users")
public class User {

  @Id
  @GeneratedValue(strategy =
    GenerationType.IDENTITY)
  private Long id;

  @Column(nullable = false,
    unique = true, length = 100)
  private String email;

  @Column(nullable = false)
  private String password;

  @Column(name = "full_name")
  private String fullName;

  @Enumerated(EnumType.STRING)
  private Role role;
  // Role = enum {STUDENT, TEACHER, ADMIN}
}

LOMBOK — REDUCING BOILERPLATE CODE

Why do we need Getters/Setters?

  • Encapsulation — private fields, accessed via methods
  • Framework requirement — JPA/Hibernate uses reflection via getter/setter
  • Validation — setter can add validation logic

Without Lombok:

public class User {
  private String email;
  public String getEmail() { return email; }
  public void setEmail(String e) { email = e; }
  // + constructor, toString, equals, hashCode
  // = 50-100 lines of boilerplate!
}

With Lombok:

@Entity
@Getter
@Setter
@NoArgsConstructor
@AllArgsConstructor
@Builder
public class User {

  @Id @GeneratedValue(strategy =
    GenerationType.IDENTITY)
  private Long id;

  private String email;
  private String password;
  private String fullName;
  private Role role;
}

Popular Lombok Annotations:

  • @Getter/@Setter — auto generate
  • @NoArgsConstructor — empty constructor
  • @AllArgsConstructor — full constructor
  • @Builder — Builder pattern
  • @Data — combines all

DTO — DATA TRANSFER OBJECT

3 types of data in Spring Boot:

TypePurposeExample
EntityMaps to DB table, contains all fieldsUser.java (@Entity)
DTOTransfers data via API, only necessary fieldsUserDTO.java
Domain ModelBusiness objects, contains business logicReport, Calculator

Why use DTO?

  • Don't expose the entire Entity (e.g., password)
  • Reduce data transfer (only needed fields)
  • Increase security (hide internal structure)
  • Decouple API contract from DB schema

Example: Entity vs DTO

// Entity — has password, internal fields
@Entity
public class User {
  private Long id;
  private String email;
  private String password;  // DO NOT expose!
  private String fullName;
  private Role role;
  private LocalDateTime createdAt;
}

// DTO — only fields needed for API
@Data
public class UserDTO {
  private Long id;
  private String email;
  // NO password
  private String fullName;
  private String role;
}

// CreateUserDTO — input for POST
@Data
public class CreateUserDTO {
  @NotBlank
  private String email;
  @Size(min = 8)
  private String password;
  private String fullName;
}

REPOSITORY — DATA ACCESS

Repository is an interface providing CRUD operations for entities — the bridge to the database.

Extends interfaces:

InterfaceProvides
CrudRepositorysave, findById, findAll, delete
JpaRepositoryCRUD + paging + sorting + flush
PagingAndSortingRepositoryCRUD + paging + sorting

Built-in methods:

  • save(entity) — insert or update
  • findById(id) — find by ID
  • findAll() — get all
  • deleteById(id) — delete by ID
  • count() — count records

Example: UserRepository

@Repository
public interface UserRepository
    extends JpaRepository<User, Long> {

  // Query by method name
  Optional<User> findByEmail(String email);
  List<User> findByRole(Role role);
  boolean existsByEmail(String email);

  // Custom query
  @Query("SELECT u FROM User u "
    + "WHERE u.fullName LIKE %:name%")
  List<User> searchByName(
    @Param("name") String name);

  // Native SQL
  @Query(value = "SELECT * FROM users "
    + "WHERE role = ?1",
    nativeQuery = true)
  List<User> findByRoleNative(String role);
}

SERVICE — BUSINESS LOGIC

Service contains business logic — the bridge between Controller and Repository.

Roles:

  • Process business rules
  • Call Repository to access DB
  • Keep Controller simple (thin controller)
  • Transaction management (@Transactional)
  • Validation, transformation, calculations

Example: UserService

@Service
@RequiredArgsConstructor
public class UserService {

  private final UserRepository userRepo;

  public List<User> getAllUsers() {
    return userRepo.findAll();
  }

  public User getUserById(Long id) {
    return userRepo.findById(id)
      .orElseThrow(() ->
        new ResourceNotFoundException(
          "User not found: " + id));
  }

  @Transactional
  public User createUser(UserDTO dto) {
    if (userRepo.existsByEmail(dto.getEmail()))
      throw new DuplicateException("Email exists");
    User user = User.builder()
      .email(dto.getEmail())
      .password(encoder.encode(dto.getPassword()))
      .fullName(dto.getFullName())
      .role(Role.STUDENT)
      .build();
    return userRepo.save(user);
  }
}

Controller handles HTTP requests from clients and sends responses.

Annotations:

AnnotationPurpose

@RestController

@RequiredArgsConstructor

  @GetMapping
  public List<User> getAll() {
    return userService.getAllUsers();

  }

  public User create(@RequestBody UserDTO dto) {
    return userService.createUser(dto);
  }

  @DeleteMapping("/{id}")
  @ResponseStatus(HttpStatus.NO_CONTENT)
  public void delete(@PathVariable Long id) {
    userService.deleteUser(id);
  }
}

REQUEST PROCESSING FLOW

1

Client Request

Client sends HTTP request (GET, POST...) to an endpoint in the Controller. E.g.: GET /api/users/1

2

Controller Handling

Controller receives request, validates input, calls the corresponding method in Service. E.g.: userService.getUserById(1)

3

Service Logic

Service processes business logic, calls Repository. E.g.: check permissions, transform data, call userRepo.findById(1)

4

Repository → Database

Repository executes SQL query through JPA/Hibernate. E.g.: SELECT * FROM users WHERE id = 1

5

Response to Client

Results return in reverse: DB → Repository → Service → Controller → JSON Response (200 OK)

GLOBAL EXCEPTION HANDLING

Use @ControllerAdvice + @ExceptionHandler for centralized error handling, returning standardized responses to clients.

Benefits:

  • Clean code — no try/catch in each controller
  • Consistent response format
  • Centralized logging
  • Easy to maintain

Custom Exception:

@ResponseStatus(HttpStatus.NOT_FOUND)
public class ResourceNotFoundException
    extends RuntimeException {
  public ResourceNotFoundException(String msg) {
    super(msg);
  }
}

Global Exception Handler:

@RestControllerAdvice
public class GlobalExceptionHandler {

  @ExceptionHandler(
    ResourceNotFoundException.class)
  public ResponseEntity<ErrorResponse>
      handleNotFound(
        ResourceNotFoundException ex) {
    return ResponseEntity
      .status(HttpStatus.NOT_FOUND)
      .body(new ErrorResponse(
        "NOT_FOUND", ex.getMessage()));
  }

  @ExceptionHandler(
    MethodArgumentNotValidException.class)
  public ResponseEntity<ErrorResponse>
      handleValidation(
        MethodArgumentNotValidException ex) {
    Map<String,String> errors = new HashMap<>();
    ex.getBindingResult().getFieldErrors()
      .forEach(err -> errors.put(
        err.getField(),
        err.getDefaultMessage()));
    return ResponseEntity.badRequest()
      .body(new ErrorResponse(
        "VALIDATION_ERROR", errors));
  }
}

PAGINATION & SORTING

Spring Data JPA supports Pagination & Sorting out of the box — no need to write SQL LIMIT/OFFSET.

Repository:

public interface UserRepository
    extends JpaRepository<User, Long> {

  // Pageable is already available from JpaRepository
  Page<User> findByRole(
    Role role, Pageable pageable);

  Page<User> findByEmailContaining(
    String email, Pageable pageable);
}

Service:

public Page<User> getUsers(
    int page, int size, String sortBy) {
  Pageable pageable = PageRequest.of(
    page, size, Sort.by(sortBy).descending());
  return userRepo.findAll(pageable);
}

Controller:

@GetMapping
public Page<User> getAll(
    @RequestParam(defaultValue = "0") int page,
    @RequestParam(defaultValue = "10") int size,
    @RequestParam(defaultValue = "id") String sort) {
  return userService.getUsers(page, size, sort);
}

// Or use Pageable directly
@GetMapping
public Page<User> getAll(Pageable pageable) {
  return userRepo.findAll(pageable);
}

CORS — CONNECTING ANGULAR & SPRING BOOT

CORS (Cross-Origin Resource Sharing) — allows Angular (port 4200) to call Spring Boot API (port 8080). By default, browsers block cross-origin requests.

Method 1: @CrossOrigin annotation

@RestController
@RequestMapping("/api/users")
@CrossOrigin(origins = "http://localhost:4200")
public class UserController { ... }

Method 2: Global config

@Configuration
public class WebConfig
    implements WebMvcConfigurer {
  @Override
  public void addCorsMappings(
      CorsRegistry registry) {
    registry.addMapping("/api/**")
      .allowedOrigins("http://localhost:4200")
      .allowedMethods("GET","POST","PUT","DELETE")
      .allowedHeaders("*")
      .allowCredentials(true);
  }
}

Method 3: Spring Security Config

@Bean
public CorsConfigurationSource
    corsConfigurationSource() {
  CorsConfiguration config =
    new CorsConfiguration();
  config.setAllowedOrigins(
    List.of("http://localhost:4200",
      "https://myapp.cmc.vn"));
  config.setAllowedMethods(
    List.of("GET","POST","PUT","DELETE"));
  config.setAllowedHeaders(List.of("*"));
  config.setAllowCredentials(true);

  UrlBasedCorsConfigurationSource source =
    new UrlBasedCorsConfigurationSource();
  source.registerCorsConfiguration(
    "/**", config);
  return source;
}

// In SecurityFilterChain
http.cors(cors ->
  cors.configurationSource(
    corsConfigurationSource()));

⚠️ DO NOT use allowedOrigins("*") with allowCredentials(true) — the browser will block it.

SPRING BOOT BEST PRACTICES

Do:

  • Constructor injection — don't use @Autowired field
  • DTO for API — don't expose Entity directly
  • @Transactional at Service layer
  • Validation with @Valid + Bean Validation
  • Global exception handler with @ControllerAdvice
  • application-{profile}.yml — separate config per environment
  • Contextual logging — log.info("User {} created", id)
  • Pagination for list endpoints
  • HTTPS for production
  • Environment variables for secrets (DO NOT commit passwords)

Avoid:

  • ❌ Field injection (@Autowired field)
  • ❌ Return Entity from Controller
  • ❌ Business logic in Controller
  • ❌ ddl-auto=update in production
  • ❌ Hardcode credentials in code
  • ❌ N+1 query problem (use @EntityGraph or fetch join)
  • ❌ Catch generic Exception — catch specific ones
  • ❌ Synchronized methods — use @Async when needed
  • ❌ No tests → prone to bugs
  • ❌ Using Optional as field or parameter
✨ MODERN TRENDS

Spring Boot 3.2+ supports Virtual Threads (Project Loom) — handles millions of concurrent requests with very little memory.
