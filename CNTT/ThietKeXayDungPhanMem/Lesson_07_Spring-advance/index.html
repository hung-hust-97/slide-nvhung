PASSWORD ENCODING — BCRYPT

KHÔNG BAO GIỜ lưu password dạng plain text. Phải dùng hash function 1 chiều với salt.

So sánh các thuật toán:

AlgorithmAn toàn?
MD5❌ Đã bị phá
SHA-1❌ Đã bị phá
SHA-256⚠️ Quá nhanh, dễ brute force
BCrypt✅ Khuyến nghị
Argon2✅ Mới nhất, mạnh nhất
PBKDF2✅ FIPS approved

Tại sao BCrypt?

  • Salt tự động — chống rainbow table
  • Adaptive cost — tăng cost khi CPU mạnh hơn
  • Slow by design — chống brute force

VD sử dụng BCrypt:

@Configuration
public class PasswordConfig {

  @Bean
  public PasswordEncoder passwordEncoder() {
    // strength = 12 (cost factor)
    return new BCryptPasswordEncoder(12);
  }
}

@Service
@RequiredArgsConstructor
public class UserService {

  private final PasswordEncoder encoder;
  private final UserRepository userRepo;

  public User register(RegisterDTO dto) {
    User user = new User();
    user.setEmail(dto.getEmail());
    // Hash password trước khi lưu
    user.setPassword(
      encoder.encode(dto.getPassword()));
    return userRepo.save(user);
  }

  public boolean login(String email, String pwd) {
    User user = userRepo.findByEmail(email)
      .orElseThrow();
    return encoder.matches(pwd, user.getPassword());
  }
}

USERDETAILSSERVICE — CUSTOM AUTHENTICATION

UserDetailsService là interface cốt lõi để Spring Security load user info từ database.

Cần implement:

@Service
@RequiredArgsConstructor
public class CustomUserDetailsService
    implements UserDetailsService {

  private final UserRepository userRepo;

  @Override
  public UserDetails loadUserByUsername(
      String email)
      throws UsernameNotFoundException {

    User user = userRepo.findByEmail(email)
      .orElseThrow(() ->
        new UsernameNotFoundException(
          "User not found: " + email));

    return org.springframework.security
      .core.userdetails.User.builder()
      .username(user.getEmail())
      .password(user.getPassword())
      .authorities(getAuthorities(user))
      .accountExpired(false)
      .accountLocked(false)
      .credentialsExpired(false)
      .disabled(!user.isActive())
      .build();
  }
}

Custom UserDetails:

@Data
@AllArgsConstructor
public class CustomUserDetails
    implements UserDetails {

  private User user;

  @Override

      getAuthorities() {

      "ROLE_" + user.getRole().name()));

  @Override
  public String getPassword() {
    return user.getPassword();
  }

  @Override
  public String getUsername() {
    return user.getEmail();
  }

  @Override public boolean isEnabled() {
    return user.isActive();
  }

LDAP & ACTIVE DIRECTORY INTEGRATION

LDAP (Lightweight Directory Access Protocol) — chuẩn cho directory services. Active Directory là implementation của Microsoft. [Wikipedia]

Khi nào cần LDAP?

  • App enterprise — user dùng AD account
  • Single Sign-On (SSO) toàn tổ chức
  • Centralized user management
  • Tích hợp với existing infrastructure

Setup:

<dependency>
  <groupId>org.springframework
    .security</groupId>
  <artifactId>
    spring-security-ldap
  </artifactId>
</dependency>

Cấu hình:

@Configuration
@EnableWebSecurity
public class LdapSecurityConfig {

  @Bean
  public SecurityFilterChain filterChain(
      HttpSecurity http) throws Exception {
    return http
      .authorizeHttpRequests(auth -> auth
        .anyRequest().fullyAuthenticated())
      .formLogin(Customizer.withDefaults())
      .build();
  }

  @Bean
  public AuthenticationManager authManager(
      BaseLdapPathContextSource contextSource) {
    LdapBindAuthenticationManagerFactory factory
      = new LdapBindAuthenticationManagerFactory(
        contextSource);
    factory.setUserDnPatterns("uid={0},ou=people");
    factory.setUserSearchBase("ou=people");
    factory.setUserSearchFilter("uid={0}");
    return factory.createAuthenticationManager();
  }

  @Bean
  public BaseLdapPathContextSource contextSource() {
    LdapContextSource source =
      new LdapContextSource();
    source.setUrl("ldap://ldap.cmc.vn:389");
    source.setBase("dc=cmc,dc=vn");
    return source;
  }
}

public void deleteUser(Long id) { ... }

@PreAuthorize("hasAuthority('CREATE_COURSE')")

SecurityConfig:

@Configuration
@EnableWebSecurity
@EnableMethodSecurity
public class SecurityConfig {

  @Bean
  public SecurityFilterChain filterChain(
      HttpSecurity http) throws Exception {
    http
      .csrf(csrf -> csrf.disable())
      .authorizeHttpRequests(auth -> auth
        .requestMatchers("/api/auth/**")
          .permitAll()
        .requestMatchers("/api/admin/**")
          .hasRole("ADMIN")
        .anyRequest().authenticated()
      )
      .sessionManagement(s -> s
        .sessionCreationPolicy(STATELESS))
      .addFilterBefore(jwtFilter,
        UsernamePasswordAuthFilter.class);
    return http.build();
  }
}

  // Kiểm tra return value
  @PostAuthorize(
    "returnObject.author == authentication.name")

@Service
public class AdminService {

  @Autowired
  private SessionRegistry sessionRegistry;

  public void forceLogout(String username) {
    sessionRegistry.getAllPrincipals()
      .stream()
      .filter(p -> ((UserDetails) p)
        .getUsername().equals(username))
      .findFirst()
      .ifPresent(principal -> {
        sessionRegistry
          .getAllSessions(principal, false)
          .forEach(SessionInformation
            ::expireNow);
      });
  }
}

JWT — JSON WEB TOKEN

JWT là token compact, self-contained cho trao đổi dữ liệu bảo mật. [Wikipedia]

Cấu trúc JWT (3 phần):

  • Header: algorithm (HS256), type (JWT)
  • Payload: claims (sub, email, roles, exp)
  • Signature: HMAC(header + payload, secret)

Luồng JWT:

  1. User login → server verify credentials
  2. Server generate JWT → trả cho client
  3. Client lưu JWT (localStorage/cookie)
  4. Mỗi request: client gửi JWT trong header Authorization: Bearer <token>
  5. Server validate JWT → cho phép/từ chối

Generate JWT:

public String generateToken(UserDetails user) {
  return Jwts.builder()
    .setSubject(user.getUsername())
    .claim("roles", user.getAuthorities())
    .setIssuedAt(new Date())
    .setExpiration(new Date(
      System.currentTimeMillis() + 86400000))
    .signWith(SignatureAlgorithm.HS256, secret)
    .compact();
}

Validate JWT:

public boolean validateToken(String token) {
  try {
    Jwts.parser()
      .setSigningKey(secret)
      .parseClaimsJws(token);
    return true;
  } catch (JwtException e) {
    return false;
  }
}

JWT AUTHENTICATION FILTER

Filter chặn mọi request, kiểm tra JWT trong header và tự động authenticate user.

@Component
@RequiredArgsConstructor
public class JwtAuthFilter
    extends OncePerRequestFilter {

  private final JwtService jwtService;
  private final UserDetailsService userDetailsService;

  @Override
  protected void doFilterInternal(
      HttpServletRequest request,
      HttpServletResponse response,
      FilterChain filterChain)
      throws ServletException, IOException {

    String authHeader = request
      .getHeader("Authorization");

    if (authHeader == null ||
        !authHeader.startsWith("Bearer ")) {
      filterChain.doFilter(request, response);
      return;
    }
    // ... validate & set context
    filterChain.doFilter(request, response);
  }
}

Validate & Set Context:

String token = authHeader.substring(7);
String email = jwtService
  .extractUsername(token);

if (email != null &&
    SecurityContextHolder.getContext()
      .getAuthentication() == null) {

  UserDetails userDetails = userDetailsService
    .loadUserByUsername(email);

  if (jwtService.isTokenValid(
      token, userDetails)) {

    UsernamePasswordAuthenticationToken authToken
      = new UsernamePasswordAuthenticationToken(
        userDetails, null,
        userDetails.getAuthorities());
    authToken.setDetails(
      new WebAuthenticationDetailsSource()
        .buildDetails(request));

    SecurityContextHolder.getContext()
      .setAuthentication(authToken);
  }
}

JWT SERVICE — TOKEN GENERATION & VALIDATION

JwtService:

@Service
public class JwtService {

  @Value("${jwt.secret}")
  private String secretKey;

  @Value("${jwt.expiration}")
  private long jwtExpiration;

  public String generateToken(
      UserDetails userDetails) {
    return generateToken(
      new HashMap<>(), userDetails);
  }

  public String generateToken(
      Map<String, Object> extraClaims,
      UserDetails userDetails) {
    return Jwts.builder()
      .setClaims(extraClaims)
      .setSubject(userDetails.getUsername())
      .setIssuedAt(new Date())
      .setExpiration(new Date(
        System.currentTimeMillis() + jwtExpiration))
      .signWith(getSignInKey(),
        SignatureAlgorithm.HS256)
      .compact();
  }
}

Validation:

public String extractUsername(String token) {
  return extractClaim(token, Claims::getSubject);
}

public boolean isTokenValid(String token,
    UserDetails userDetails) {
  String username = extractUsername(token);
  return username.equals(
    userDetails.getUsername())
    && !isTokenExpired(token);
}

private boolean isTokenExpired(String token) {
  return extractExpiration(token).before(
    new Date());
}

private Key getSignInKey() {
  byte[] keyBytes = Decoders.BASE64
    .decode(secretKey);
  return Keys.hmacShaKeyFor(keyBytes);
}

  expiration: 86400000   # 24 hours

REFRESH TOKEN PATTERN

Vấn đề: Access Token nên có thời hạn ngắn (15 phút) để bảo mật, nhưng user không muốn login liên tục → giải pháp: Refresh Token.

Cách hoạt động:

  • Login → server trả 2 tokens: Access (15 min) + Refresh (7 days)
  • Client lưu refresh token an toàn (httpOnly cookie)
  • Khi access token hết hạn → client gửi refresh token để lấy access mới
  • Refresh token có thể bị revoke server-side

Lợi ích:

  • Access token ngắn → giảm rủi ro nếu bị leak
  • UX tốt — không cần login lại
  • Server có thể logout user (revoke refresh)

Endpoint refresh:

@RestController
@RequestMapping("/api/auth")
@RequiredArgsConstructor
public class AuthController {

  private final AuthService authService;

  @PostMapping("/login")
  public AuthResponse login(
      @RequestBody LoginRequest req) {
    return authService.authenticate(req);
    // { accessToken, refreshToken }
  }

  @PostMapping("/refresh")
  public AuthResponse refresh(
      @RequestBody RefreshRequest req) {
    return authService.refreshToken(
      req.getRefreshToken());
  }

  @PostMapping("/logout")
  public void logout(
      @RequestBody RefreshRequest req) {
    authService.revokeRefreshToken(
      req.getRefreshToken());
  }
}

API KEY AUTHENTICATION

API Key dùng cho service-to-service authentication, không phải user authentication. Phù hợp cho machine clients (third-party integrations).

Đặc điểm:

  • String dài, random, unique
  • Truyền qua HTTP header (X-API-Key)
  • Có thể revoke server-side
  • Có rate limit per key
  • Có scopes/permissions

Tạo API Key:

public String generateApiKey() {
  byte[] randomBytes = new byte[32];
  new SecureRandom().nextBytes(randomBytes);
  return Base64.getUrlEncoder()
    .withoutPadding()
    .encodeToString(randomBytes);
}
// VD: "Xx1Yy2Zz3..." (43 ký tự)

API Key Filter:

@Component
public class ApiKeyFilter
    extends OncePerRequestFilter {

  @Autowired
  private ApiKeyService apiKeyService;

  @Override
  protected void doFilterInternal(
      HttpServletRequest req,
      HttpServletResponse res,
      FilterChain chain)
      throws ServletException, IOException {

    String apiKey = req.getHeader("X-API-Key");

    if (apiKey != null) {
      ApiKeyEntity key = apiKeyService
        .validateAndGet(apiKey);
      if (key != null && key.isActive()) {
        UsernamePasswordAuthenticationToken auth =
          new UsernamePasswordAuthenticationToken(
            key.getClientName(), null,
            key.getAuthorities());
        SecurityContextHolder.getContext()
          .setAuthentication(auth);
      }
    }

    chain.doFilter(req, res);
  }
}

HTTPS, SSL/TLS & CERTIFICATES

HTTPS = HTTP + TLS encryption — bắt buộc cho production để bảo vệ dữ liệu truyền tải.

Tại sao cần HTTPS?

  • Encryption — chống man-in-the-middle
  • Authentication — verify server identity
  • Integrity — chống thay đổi data
  • SEO ranking — Google ưu tiên HTTPS
  • HTTP/2 & HTTP/3 — chỉ chạy trên HTTPS
  • Modern browser features — Service Worker, Geolocation chỉ trên HTTPS

Lấy SSL certificate:

  • Let's Encrypt — miễn phí, auto-renew
  • DigiCert, Sectigo — commercial CA
  • Self-signed — chỉ cho dev

      .includeSubDomains(true))

    // Chống clickjacking
    .frameOptions(frame -> frame.deny())

    // Chống MIME sniffing
    .contentTypeOptions(Customizer.withDefaults())

    // CSP
    .contentSecurityPolicy(csp -> csp
      .policyDirectives(
        "default-src 'self'; " +
        "script-src 'self'; " +
        "style-src 'self' 'unsafe-inline'; " +
        "img-src 'self' data: https:; " +
        "frame-ancestors 'none'"))

    // Referrer
    .referrerPolicy(ref -> ref
      .policy(ReferrerPolicy
        .STRICT_ORIGIN_WHEN_CROSS_ORIGIN)));

2 loại Encryption:

Keys1 key chungPublic + Private key
SpeedNhanhChậm hơn

Encrypt sensitive field trong DB:

@Service
public class EncryptionService {

  @Value("${encryption.key}")
  private String secretKey;

  public String encrypt(String plainText) {
    Cipher cipher = Cipher.getInstance(
      "AES/GCM/NoPadding");
    cipher.init(Cipher.ENCRYPT_MODE,
      getKeyFromString(secretKey));
    byte[] encrypted = cipher.doFinal(
      plainText.getBytes());
    return Base64.getEncoder()
      .encodeToString(encrypted);
  }
}

@Converter
public class EncryptedStringConverter
    implements AttributeConverter
      <String, String> {

      String plainText) {
    return encryptionService.encrypt(plainText);
  }

  @Override
  public String convertToEntityAttribute(
      String encrypted) {
    return encryptionService.decrypt(encrypted);
  }
}

SQL INJECTION — VÍ DỤ & PHÒNG CHỐNG

❌ Code có lỗ hổng:

// String concatenation - VERY BAD!
String email = request.getParameter("email");
String sql = "SELECT * FROM users WHERE " +
  "email = '" + email + "'";
Statement stmt = conn.createStatement();
ResultSet rs = stmt.executeQuery(sql);

// Attacker nhập:
// email = ' OR '1'='1
// Query thành:
// SELECT * FROM users WHERE email = ''
//   OR '1'='1
// → Trả về TẤT CẢ users!

// Hoặc nguy hiểm hơn:
// email = '; DROP TABLE users; --
// → Xóa cả bảng!

✅ Cách phòng chống:

// 1. Prepared Statement
String sql = "SELECT * FROM users " +
  "WHERE email = ?";
PreparedStatement ps =
  conn.prepareStatement(sql);
ps.setString(1, email);
ResultSet rs = ps.executeQuery();
// Driver tự escape special chars

// 2. JPA - tự động an toàn
@Query("SELECT u FROM User u " +
  "WHERE u.email = :email")
User findByEmail(@Param("email") String email);

// 3. Spring Data - method name
Optional<User> findByEmail(String email);
// Tự sinh prepared statement

Best practices:

  • Luôn dùng parameterized queries
  • Validate input (whitelist format)
  • Least privilege — DB user không có DROP
  • WAF (Web Application Firewall)

CSRF — CROSS-SITE REQUEST FORGERY

CSRF — kẻ tấn công lừa user thực hiện request không mong muốn (VD: chuyển tiền) khi user đang đăng nhập trang web khác.

Cách tấn công:

  1. User đăng nhập vào bank.com
  2. User truy cập evil.com
  3. evil.com có form ẩn POST đến bank.com
  4. Browser tự gửi cookie session → bank tin tưởng → chuyển tiền

Cách phòng chống:

  • CSRF Token — random token cho mỗi session, server kiểm tra mỗi request
  • SameSite Cookie — chỉ gửi cookie cho cùng origin
  • Custom headers — yêu cầu X-Requested-With
  • Stateless API + JWT — không cần CSRF (vì không dùng cookie)

Spring Security CSRF:

@Configuration
@EnableWebSecurity
public class SecurityConfig {

  @Bean
  public SecurityFilterChain filterChain(
      HttpSecurity http) throws Exception {
    http
      // Bật CSRF cho web app truyền thống
      .csrf(csrf -> csrf
        .csrfTokenRepository(
          CookieCsrfTokenRepository
            .withHttpOnlyFalse()))

      // Hoặc disable cho REST API stateless
      // .csrf(csrf -> csrf.disable())

      .authorizeHttpRequests(...)
      .build();
  }
}

REST API với JWT thường disable CSRF vì token lưu trong header (không phải cookie tự động).

RATE LIMITING — CHỐNG BRUTE FORCE

Rate Limiting giới hạn số request từ 1 IP/user trong khoảng thời gian → chống brute force, DoS, abuse.

Strategies:

  • Fixed Window — N requests / phút
  • Sliding Window — chính xác hơn
  • Token Bucket — burst-friendly
  • Leaky Bucket — smooth rate

Bucket4j với Spring Boot:

<dependency>
  <groupId>com.bucket4j</groupId>
  <artifactId>bucket4j-core</artifactId>
</dependency>

VD: Login rate limit

@Service
public class RateLimitService {

  private final Map<String, Bucket> cache =
    new ConcurrentHashMap<>();

  public Bucket resolveBucket(String key) {
    return cache.computeIfAbsent(key,
      k -> Bucket.builder()
        .addLimit(Bandwidth.classic(5,
          Refill.intervally(5,
            Duration.ofMinutes(1))))
        .build());
  }
}

@PostMapping("/login")
public AuthResponse login(
    @RequestBody LoginRequest req,
    HttpServletRequest http) {
  String ip = http.getRemoteAddr();
  Bucket bucket = rateLimitService
    .resolveBucket(ip);

  if (!bucket.tryConsume(1)) {
    throw new TooManyRequestsException(
      "Try again later");
  }
  return authService.authenticate(req);
}

2FA yêu cầu 2 lớp xác thực: password + thiết bị (điện thoại) → giảm 99% account takeover.

TOTP (Google Authenticator)✅ An toàn
Push notification✅ UX tốt
Hardware key (YubiKey)✅✅ Mạnh nhất
Biometric✅ Touch/Face ID

TOTP Flow:

  1. User login với password
  2. Server yêu cầu OTP 6 số
  3. App (Google Authenticator) sinh OTP
  4. Server verify OTP → cho phép

@Service
public class TwoFactorService {

  // Tạo secret cho user
  public String generateSecret() {
    return new DefaultSecretGenerator()
      .generate();
  }

  // Tạo QR code cho user scan
  public String getQRCodeUri(
      String secret, String email) {
    return new QrData.Builder()
      .label(email)
      .secret(secret)
      .issuer("CMC University")
      .algorithm(HashingAlgorithm.SHA1)
      .digits(6)
      .period(30)
      .build()
      .getUri();
  }

  // Verify OTP từ user
  public boolean verifyCode(
      String secret, String code) {
    return new DefaultCodeVerifier(
      new DefaultCodeGenerator(),
      new SystemTimeProvider())
      .isValidCode(secret, code);
  }
}

AUDIT LOGGING — THEO DÕI HÀNH VI

Audit Log ghi lại các hành động quan trọng — bắt buộc cho compliance (GDPR, HIPAA, PCI DSS).

Cần log:

  • Authentication (login, logout, failed)
  • Authorization (access denied)
  • Data changes (CRUD trên dữ liệu nhạy cảm)
  • Admin actions (tạo user, đổi role)
  • Security events (brute force, IP lạ)

Audit Entity:

@Entity
@Data
public class AuditLog {

  private Long id;
  private String username;
  private String action;
  private String entityType;
  private String entityId;
  private String details;
  private String ipAddress;
  private LocalDateTime timestamp;
}

Spring Security Event Listener:

@Component
@RequiredArgsConstructor
public class SecurityEventListener {

  private final AuditLogRepository auditRepo;

  @EventListener
  public void onLoginSuccess(
      AuthenticationSuccessEvent event) {
    AuditLog log = new AuditLog();
    log.setUsername(event.getAuthentication()
      .getName());
    log.setAction("LOGIN_SUCCESS");
    log.setTimestamp(LocalDateTime.now());
    auditRepo.save(log);
  }

  @EventListener
  public void onLoginFailure(
      AbstractAuthenticationFailureEvent event) {
    AuditLog log = new AuditLog();
    log.setUsername((String) event
      .getAuthentication().getPrincipal());
    log.setAction("LOGIN_FAILED");
    log.setDetails(event.getException()
      .getMessage());
    auditRepo.save(log);
  }
}

@Configuration
@EnableWebSecurity
@EnableMethodSecurity
@RequiredArgsConstructor
public class SecurityConfig {

  private final UserDetailsService userDetailsService;

      HttpSecurity http) throws Exception {

      .csrf(csrf -> csrf.disable())
      .cors(Customizer.withDefaults())

        .sessionCreationPolicy(STATELESS))

          .hasAnyRole("TEACHER","ADMIN")

      .addFilterBefore(jwtFilter,
        UsernamePasswordAuthenticationFilter.class)
      .build();
  }
}

SECURITY BEST PRACTICES CHECKLIST

Authentication:

  • ✅ BCrypt password hashing (cost ≥ 12)
  • ✅ JWT với short expiration + refresh token
  • ✅ 2FA cho tài khoản quan trọng
  • ✅ Rate limit login endpoint
  • ✅ Account lockout sau N lần fail
  • ✅ Strong password policy

Authorization:

  • ✅ RBAC với @PreAuthorize
  • ✅ Default deny — explicitly allow
  • ✅ Validate ownership ở method level
  • ✅ API Gateway cho centralized auth

Network & Data:

  • ✅ HTTPS only (HSTS)
  • ✅ TLS 1.2+ với strong ciphers
  • ✅ CORS chỉ cho phép origins cần thiết
  • ✅ Encryption at rest (DB, backups)
  • ✅ Sensitive data masking trong logs

Input & Output:

  • ✅ Validate tất cả input (whitelist)
  • ✅ Parameterized queries (no SQL injection)
  • ✅ Output encoding (no XSS)
  • ✅ Content Security Policy
  • ✅ File upload: type, size, virus scan
